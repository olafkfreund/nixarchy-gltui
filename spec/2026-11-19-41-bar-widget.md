# Spec: A bar widget with running and failed counts

The approved intent's recommendations are taken as decisions:

1. a second, widget-only plugin, fed by a status file the panel writes;
2. "failed" counts projects whose latest finished pipeline the panel has
   seen failed;
3. no background polling while the panel is closed;
4. a left click toggles the panel;
5. nixarchy does not place the widget;
6. it is designed so nixarchy-ghtui #62 can copy it.

## Design

```mermaid
flowchart LR
  P[PipelinesPanel adopt()] -->|Model.barStatus| F[(status file)]
  F -->|FileView watch| W[bar widget, one per screen]
  W -->|click: omarchy-shell shell toggle| P
```

### The widget plugin

A new directory `bar-widget/` is a plugin of its own, id
`olafkfreund.gitlab-pipelines-bar`, installed beside the panel plugin. A
separate plugin keeps the panel plugin's manifest unchanged: enabling,
disabling, Setup → Plugins and its `plugins[]` settings behave as today.
Adding `bar-widget` to the panel plugin would change them
(`PluginRegistry.qml` lines 556-575, `shell.qml` lines 1965-1973). The
owner's `io.github.olafkfreund.nixi-button` is the same pattern: a
widget-only plugin that toggles another plugin's surface.

- **`bar-widget/manifest.json`:**
  - `schemaVersion: 1`, `id`, `name` "GitLab Pipelines bar", `version`
    equal to the panel's (1.16.0), `author`, `description`.
  - `"kinds": ["bar-widget"]`, `"entryPoints": {"barWidget": "BarWidget.qml"}`.
  - `barWidget`: `displayName` "GitLab Pipelines", `category`
    "Development", `allowMultiple: false`, `defaultSection: "right"`.
  - No `keepLoaded`.
- **`bar-widget/BarWidget.qml`:**
  - **Base and button.** It extends `qs.Ui` `BarWidget` (`moduleName` =
    the id). It holds one `Ui.WidgetButton` filling it, so the whole
    widget, counts included, is the click and tooltip target.
  - **Button properties.**
    - `text` is the label from `BarModel.view`: the GitLab glyph ``
      written as an escape, then the counts.
    - `active` (the bar's urgent colour) is set when something failed or
      polling stopped.
    - `dimmed` is set in `none` and `rate`.
    - `tooltipText` is the view's tooltip.
    - The button sets `Accessible.name` from the view.
  - **Vertical bars.** On a vertical bar (`vertical` from the base), the
    label's parts are joined with `"\n"` instead of spaces.
  - **Click.** `onPressed` runs `Quickshell.execDetached(["omarchy-shell",
    "shell", "toggle", "olafkfreund.gitlab-pipelines", "{}"])`: an argument
    list, as gmessages' widget does.
  - **Reading the status.**
    - A `FileView` on the status path has `watchChanges: true` and
      `printErrors: false`.
    - `onLoaded` passes its `text()` to `BarModel.view`; `onLoadFailed`
      passes `""`.
    - Empty text means `none`, so a stale cached text after a failed
      load or a deleted file is never shown.
    - `onFileChanged` reloads it.
  - **Rate-limit expiry.** A one-shot `Timer` re-evaluates the view at
    `recheckAt`, with the interval clamped to 100 ms … 24 h.
  - **Text.** All text is plain: `WidgetButton` draws plain text, and
    the bar's tooltip uses `Text.PlainText` (`Bar.qml` line 1858).
- **`bar-widget/BarModel.js`**, pure functions (the widget cannot import
  the panel plugin's files):
  - `view(text, now, vertical)` → `{state, label, tooltip, accessible,
    active, dimmed, recheckAt}`.
  - Empty, unparseable or `version !== 1` text → `none`.
  - Numbers are clamped to non-negative integers. `reason` is cut to 120
    characters.
  - A `rate` whose `cooldownUntil` has passed is shown as `ok` if
    `countsAt > 0`, else `none`.
- **`bar-widget/LICENSE`**: a copy of the root licence.

### The status file

- **Path:** `$XDG_RUNTIME_DIR/omarchy-gitlab-pipelines-<WAYLAND_DISPLAY>.json`.
  - Both sides compute it from `Quickshell.env` and expose it as a
    property tests can override.
  - If either variable is empty, the path is `""`: the panel writes
    nothing and the widget shows `none`.
  - The runtime directory always exists, is private to the user (0700),
    and is emptied at logout. The Wayland display name keeps two sessions
    of one user apart.
  - The state directory suggested in the intent may not exist, QML cannot
    create it, and it would keep a stale status across reboots.
- **Shape**, written whole with a `FileView` (`atomicWrites: true`,
  `printErrors: false`) and `setText`, as the shell writes `shell.json`
  (`shell.qml` lines 146-171):

  ```json
  {"version":1,"instance":"<random>","host":"gitlab.com","state":"ok",
   "running":2,"failed":1,"countsAt":1795113908000,"cooldownUntil":0,
   "reason":"","writtenAt":1795113909000}
  ```

  `state` is `none`, `ok`, `stopped` or `rate`. The only free text is
  `reason`: the panel's own error string.

### The panel side

- **`Model.barCounts(repos)`** in `PipelinesModel.js` → `{running, failed}`.
  - It skips archived, CI-disabled, blocked and errored projects.
  - `running` sums the same per-project number the rows show: `repo.active`,
    or the cached `in_progress` runs when `active` is unset
    (`PipelinesModel.js` line 267).
  - `failed` counts projects where `latest(repo.runs || [])` has
    `conclusion === "failed"`.
- **`Model.barStatus(polling, configError, host, instance, now)`** → the
  object above. The first matching rule wins:
  1. `stopped`, with `reason` from the first of: `configError`;
     `polling.auth` (the sign-in or setup stop, with `polling.error`);
     `polling.catalogueError`.
  2. `rate`, with `cooldownUntil = polling.cooldown`, when that is in the
     future.
  3. `none`, when `polling.countsAt` is unset.
  4. `ok`.

  Counts and `countsAt` are carried in every state. `polling.mrs.error`
  and transient network errors are never read.
- **`Polling.countsAt`**:
  - It is a new field in `create()`, left unset by `resetHost`.
  - `activity()` sets it to `now` (`Polling.js` line 342; summaries call
    it too).
  - A finished catalogue with no pollable project (none, or only
    archived, CI-disabled or blocked ones) also sets it, so such an
    account shows `ok` with zero counts instead of `none` for ever.
  - `run`, job and bridge replies never set it.
- **`configError`**: a new panel property. `configure()`'s `catch` sets it
  as well as `error`, and a successful `configure()` clears it. `adopt()`
  does not touch it, so a later watch reply cannot erase a configuration
  stop.
- **Publishing**:
  - New panel members:
    - `statusPath`;
    - `statusInstance`, set once at `Component.onCompleted` from
      `Date.now()` plus a random suffix;
    - a `FileView` writer;
    - `publishStatus()`.
  - **Change detection.** `publishStatus()` serialises `barStatus`
    without `writtenAt` and writes only when that differs from the last
    *successful* write, which it records in the writer's `onSaved`. A
    failed write (`onSaveFailed`) leaves it unrecorded, so the next call
    retries.
  - **When it runs:**
    - at the end of `adopt()`, which runs after every reply, open or
      closed (`receivePage`, `PipelinesPanel.qml` lines 621-636), and
      after a host reset;
    - at the end of `configure()`, success or failure;
    - at `Component.onCompleted`, which writes `state: none` with the new
      instance, so a shell restart or plugin reload shows the no-data
      state;
    - at `Component.onDestruction`, which writes `none` on a best-effort
      basis, so disabling or reloading the panel does not leave its last
      counts showing.
- **The watch running-count fix** in `Polling.complete()`, `run` branch
  (line 451):
  - Before `mergeRuns`, note whether the cached run was counted: its
    status was `in_progress` and it was not `awaitingFinal`. An
    `awaitingFinal` run has already left GitLab's total in `activity()`
    (lines 345-359).
  - If it was counted, the resolved run is not `in_progress`, and
    `r.activeFromTotal` is set, then `r.active = Math.max(running,
    (r.active || 0) - 1)`.
  - The existing `Math.max(r.active, running)` stays for every other case.

### The widget's states

| State | Label | Colour | Tooltip |
| --- | --- | --- | --- |
| `none` | glyph | dimmed | "Open GitLab Pipelines to load" |
| `ok` | glyph, then `●N` if running > 0, then `✕N` if failed > 0 | urgent if failed > 0 | "GitLab Pipelines · <host>", then "N running pipelines, N failed projects", then "Project counts from HH:MM; watched pipelines are live" |
| `stopped` | glyph and `!` | urgent | "GitLab Pipelines stopped: <reason>. Open the panel to fix it." |
| `rate` | glyph and the last counts | dimmed | "GitLab paused until HH:MM", followed by the `ok` lines only when `countsAt > 0` |

The units are singular or plural as needed. The accessible name is the
tooltip's lines joined with ", ". `HH:MM` uses the local time format.

### Packaging and docs

- **`flake.nix`**:
  - A second package, `packages.<system>.bar`, copies `bar-widget/`.
    `packages.default` stays the panel.
  - `checks.plugin` also runs `node tests/bar.cjs`, with `BarModel.js`
    staged from `packages.bar`.
  - It checks the `bar` package's file list (`manifest.json`,
    `BarWidget.qml`, `BarModel.js`, `LICENSE`, no symlinks), the
    manifest's id, kinds and entry point, and that its `version` equals
    the panel's.
- **`tests/qml-smoke.py`** takes the widget directory from `source /
  "bar-widget"` when present. A package-only run (`./result`) skips the
  widget stage and says so.
- **README:**
  - **"Bar widget" section:**
    - what it shows and its two units;
    - freshness: as of the last project read, with watches live;
    - the states.
  - **Install:**
    - Git: link `bar-widget` as
      `~/.config/omarchy/plugins/olafkfreund.gitlab-pipelines-bar`, then
      `omarchy bar put olafkfreund.gitlab-pipelines-bar`;
    - Nix: the `bar` package;
    - nixarchy: a follow-up entry.
  - **Known limits:**
    - counts are stale while the panel is closed;
    - `failed` covers only pipelines the panel has seen;
    - two shells on one Wayland display would share the file.
  - **"Remove"**: the widget's link and its bar entry.
  - **"Refresh and errors"**: the watch fix.
- **`manifest.json`**: 1.16.0. **`keybindings.sh`**: unchanged.

## Alternatives rejected

- **`bar-widget` and `service` kinds on the panel plugin (intent Q1 b):**
  - it changes enable and list behaviour for every user;
  - the panel would have to read settings from a bar entry;
  - the kept service survives a reload with stale counts;
  - a replacement bar gives the widget no service.
- **Walking host objects to reach the panel:** outside the documented API.
- **The state directory for the file:** it may be missing, cannot be
  created from QML, and outlives the session.
- **A Python helper to write the file:** a process per change, where a
  `FileView` already writes atomically.
- **`BarIconButton` with sibling count labels:** it sizes to the icon slot,
  so the counts would be outside the click and tooltip area (gmessages had
  to add a separate `MouseArea` for its badge).
- **Counting failed pipelines rather than projects:** that number grows
  with history.

## Risks

- **Second install step.** Without it there is no widget; the README says
  so.
- **`FileView` runtime behaviour** (creating a missing file, watching a
  path that does not exist yet, atomic renames) is Quickshell's. The smoke
  test exercises all three on one path; if one fails, the plan's step
  records the workaround.
- **A missing glyph** in a non-Nerd font shows a box.
- **Hosts.** p620 and razer get it on the 1.16.0 deploy; p510 is
  untouched. Placing the widget on p620 is a manual step for the owner.

## Verification

- **`node tests/bar.cjs`** (new), `BarModel.view`:
  - every state;
  - empty, bad and old-version text → `none`;
  - clamped numbers and a cut `reason`;
  - `rate` → `ok` after expiry with counts, `rate` → `none` without;
  - no `HH:MM` for an unset `countsAt`;
  - singular and plural units;
  - zero counts showing the glyph only;
  - the vertical label;
  - `recheckAt`.
- **`node tests/model.cjs`**:
  - `barCounts`: skipped projects, a repo with no `runs`, `active` unset
    vs set, failed vs a newer success;
  - `barStatus`: precedence (config error, auth stop, catalogue error,
    rate, none, ok), `mrs.error` and a network `polling.error` ignored.
- **`node tests/polling.cjs`**:
  - `countsAt` is set by activity, summary and an empty catalogue, but
    not by `run` or jobs replies; `resetHost` clears it.
  - A closed watch with an activity total of 1 → `active` 0.
  - Two running, one finishing → 1.
  - An `awaitingFinal` run's final reply does not decrement (Codex's 101
    → 100 case).
  - A non-total project is unchanged.
- **`python3 -m unittest discover -s tests`**: still passes.
- **QML smoke test, in the headless VM only:**

  ```bash
  nix build ./ci#checks.x86_64-linux.qml-smoke -L --override-input gltui path:<worktree>
  ```

  All of the following use one status path:
  - The widget starts with no file and shows `none`.
  - The panel creates the file at start (`none`, with an instance), then
    writes `ok` after the fixture loads. The widget follows each write.
  - Repeated atomic writes keep it in sync.
  - An unchanged status does not rewrite the file.
  - A configuration error writes `stopped`; a following watch reply
    keeps it; a valid configuration clears it.
  - A host change writes `none`.
  - A watch completing while closed publishes without advancing
    `countsAt`.
  - Deleting the file, or emptying it, shows `none`; recreating it shows
    the new status.
  - Two widget instances (two fake `bar` objects, one vertical) show the
    same counts with no requests.
  - A click runs the toggle command, captured through a fake
    `omarchy-shell` on `PATH`.
- **`nix build .#bar` and `nix flake check`**: the package contents and
  version check pass.
- **Manual on p620 after the deploy:** link the widget, put it on the bar,
  and compare its counts with the panel.
