# Spec: Show what GitLab already tells us on each row

## Design

### 1. Helper: three job fields pass through (`gitlab.py`)

`job(row)` (`gitlab.py:158-162`) adds three fields. All other fields and
statuses are unchanged.

| Output field | From GitLab | Rule |
|---|---|---|
| `failure_reason` | `failure_reason` | `plain()` if it is a string, otherwise `""` |
| `duration` | `duration` | the number if it is an `int` or `float` (not a `bool`), finite and `>= 0`; otherwise `None` |
| `queued_duration` | `queued_duration` | same rule as `duration` |

`pipeline()` does not change. Pipelines keep their computed time, as
approved.

### 2. Model: raw times on rows, and pure formatters (`PipelinesModel.js`)

Rows keep every field they have today. `info` is still the rebuild-time
text, so existing tests and checks keep meaning the same. They also gain raw
inputs, so the delegate can recompute times each second:

| Row kind | New raw fields |
|---|---|
| `repo` | `checked` (ISO string, from `repo.checked`) |
| `run` | `started`, `ended` (the `duration()` inputs), `finished` (`run.completed_at` only, never `updated_at`), `fetched` (`detail.updated`) |
| `stage` | `started` and `ended` from `stage.span`, and `done` / `total` (job counts) |
| `job` | `started` ← `started_at`; `ended` and `finished` ← `completed_at`; `complete` ← `job.status === "completed"` (a boolean); `serverDuration` ← `duration`; `queued` ← `queued_duration`; `reason` ← `failure_reason` |

**Missing values have one form per field,** so `syncRows`'s `!==`
comparison is stable:
- `""` for the time and reason strings;
- `null` for `serverDuration` and `queued`;
- `false` for `complete`.

`undefined` never appears. A running job has no `completed_at`, so
`ended` and `finished` are `""`. Nothing ever writes `now` into them, which
would freeze the live count.

**Run subtitle:** the subtitle no longer embeds
`" · jobs fetched HH:MM:SS UTC"`. That moves to the live subtitle (below).
The rest of the subtitle text is unchanged, apart from the ref.

New pure functions, all ES5:

- **`shortRef(ref)`:** `/^refs\/merge-requests\/(\d+)\/(head|merge|train)$/`
  becomes `"!" + N`. Every other value is returned unchanged.
  - The run subtitle uses `shortRef(run.head_branch)`.
  - `runMatches()` searches both the raw ref and `shortRef(ref)`, so `!123`,
    `123` and the raw path all find the pipeline.
- **`ago(iso, now)`:** returns `""` when the time is missing or invalid.
  Otherwise, with `s = floor((now - t) / 1000)`:

  | Seconds | Text |
  |---|---|
  | `s < 10`, including a future time (clock skew) | `just now` |
  | `s < 60` | `Ns ago` |
  | `s < 3600` | `Nm ago` |
  | `s < 86400` | `Nh ago` |
  | otherwise | `Nd ago` |

  Values always round down.
- **`seconds(n)`:** formats a seconds count the same way `duration()` does
  (`45s`, `1m 2s`, `1h 5m`). `duration()` is refactored to use it, with
  identical output.
- **`reasonText(code)`:** a fixed map of GitLab's documented codes to short
  words. Anything else has its underscores replaced with spaces.

  | Code | Text |
  |---|---|
  | `script_failure` | `script failure` |
  | `runner_system_failure` | `runner error` |
  | `stuck_or_timeout_failure` | `timed out` |
  | `job_execution_timeout` | `timed out` |
  | `api_failure` | `API error` |
  | `missing_dependency_failure` | `missing dependency` |
  | `runner_unsupported` | `runner unsupported` |
  | `scheduler_failure` | `scheduler error` |
  | `data_integrity_failure` | `data error` |
  | `unknown_failure` | `unknown failure` |

  An empty code gives `""`.
- **`infoText(row, now)`:** the text of the info column. Where today's
  delegate expression and the new one share a field, they are identical.
  Live values come from `now`. Parts are joined with `" · "`, and empty
  parts are dropped.

  | Row kind | Parts |
  |---|---|
  | `repo` | `row.info` (unchanged: `N running`, `not checked`, `archived`, …); then `checked <ago>` when `row.checked` is set and `row.info` ends with `running` |
  | `run` | `row.status`; then the live duration from `started` / `ended` at `now`; then `ago(row.finished, now)` when `finished` is set |
  | `stage` | `row.status`; then `done/total jobs`; then the live span duration |
  | `job` | `row.status`; then `reasonText(row.reason)` when the status is `failed` or `allowed to fail`; then the duration; then `queued <seconds(queued)>` when `queued > 0`; then `ago(row.finished, now)` |
  | `more`, `message` | today's expression, unchanged: `status + (info ? " · " + info : "")`. A loading row keeps `queued` and an error row keeps `error`; a `more` row stays blank, because both fields are empty. |

  The `repo` row appends `checked <ago>` only when `ago()` returns
  non-empty text, so an invalid timestamp never leaves a dangling
  `checked`.

  Today's delegate shows `status + " · " + info` for everything except
  `repo`. The new rows reproduce that, plus the new parts.
- **Which duration a job shows:** when `row.complete` is true and
  `serverDuration` is a number, the duration is
  `seconds(round(serverDuration))`, and `0` is valid. A finish timestamp is
  not required. Otherwise the duration is computed live from `started` /
  `ended` at `now`, as `duration()` does.
  - A running job therefore always counts up, even if GitLab sent a
    snapshot `duration`.
  - "… ago" needs a real `finished` time, separately: a finished job
    without one shows its duration and no "ago".
- **Stage times:** these keep today's rule (`PipelinesModel.js:63-67`):
  the earliest start, and the latest finish only when every job has
  completed. A stage's duration is that elapsed span, not the sum of its
  jobs' durations.
- **`subtitleText(row, now)`:** `row.subtitle`, plus
  `" · jobs fetched " + ago(row.fetched, now)` for a `run` row when
  `fetched` is set.
- **`syncRows`:** `shownFields` (`PipelinesModel.js:169`) adds the new raw
  fields. A poll that changes only a timestamp then still refreshes the
  delegate's `rowData`. The fields hold strings, numbers, `null` or
  booleans, with one missing form per field, so the existing `!==`
  comparison stays correct.

### 3. Panel: the delegate binds to `now` (`PipelinesPanel.qml`)

- **Info text** (`:488`):
  `text: Model.infoText(modelData, root.now)`.
- **Subtitle text** (`:474`):
  `text: Model.subtitleText(modelData, root.now)`. Its `visible` and the row
  height still test `modelData.subtitle`, so the height never changes on a
  tick.
- **The clock:** `root.now` already ticks every second while the panel is
  open (`:287`). `open()` sets `now = Date.now()` first, so that a reopened
  panel never shows a stale clock for a second.
- **Unchanged:** `rebuild()`, the selection, scrolling, zoom-settle and the
  #26 error strip. The once-a-second update re-evaluates two text bindings
  per visible delegate.
- **Horizontal layout changes on a tick.** A new info text can change
  `info.implicitWidth`, and so `info.width` (`:486`) and the title column
  beside it (`:461`). Titles may then elide differently when a timer
  crosses a digit or unit boundary, for example `59s` → `1m 0s`. Row height
  does not depend on the live text (`:442`), so this is horizontal layout
  only: no scroll jump and no binding loop. The smoke test checks that the
  cursor and `contentY` stay put across such a boundary. A new layout
  mechanism is only warranted if that check fails.

## Alternatives rejected

- **Rebuild every second:** this repeats filtering, sorting, grouping and
  `syncRows`, and reads list geometry, which the zoom code warns about. It
  was rejected in the intent.
- **Store formatted strings only:** the delegate could not recompute them
  each second.
- **Pipeline durations from single lookups:** they are occasional and are
  overwritten by list merges. Rejected in the intent.
- **Show the raw `failure_reason` code:** hard to read. The fallback shows
  it with spaces anyway.

## Risks

- **Width:** a failed job's info can read
  `failed · script failure · 3m 12s · queued 40s`. The column is capped at 35%
  and elides from the right (`:486-492`), so the queue time is cut first,
  then the duration. The microVM screenshot is checked at 100% and 150%
  zoom.
- **API fields:** `failure_reason`, `duration` and `queued_duration` on job
  list entries come from GitLab's documented job API. They have not been
  checked against a live reply. The helper treats them as optional, so
  their absence only means the old display. The manual check after deploy
  confirms them on a real failed job.
- **Cost:** two bindings per visible delegate re-evaluate each second,
  which is a few dozen string builds, plus horizontal relayout of rows
  whose info width changed.
- **Hosts:** a panel and helper change, released through the usual chain to
  p620 and razer. p510 stays on 1.0.0.

## Verification

- `python3 -m unittest discover -s tests`, with new `tests/test_gitlab.py`
  cases:
  - `job()` passes `failure_reason`, `duration` and `queued_duration`
    through;
  - a missing, `null`, negative, `bool` or string duration becomes `None`;
  - a non-string `failure_reason` becomes `""`;
  - a reason with control characters is cleaned by `plain()`.
- `node tests/model.cjs`:
  - `shortRef`: the `/head`, `/merge` and `/train` forms; a branch, a tag
    and a SHA stay unchanged; `refs/merge-requests/x/head` stays unchanged;
  - `runMatches` finds `!123` and `123`;
  - `ago`: every boundary (9s, 10s, 59s, 60s, 3599s, 3600s, 86399s,
    86400s), a future time, and missing and invalid input;
  - `reasonText`: two known codes, an unknown code, and an empty code;
  - `infoText` for each kind:
    - a running job counts up as `now` advances, even when it has a numeric
      `serverDuration`;
    - a finished job uses `serverDuration`, including `0`, also without a
      finish time;
    - a finished job with `finished` shows "ago", and one without shows
      none;
    - a loading row shows `queued` and an error row shows `error`, as
      today;
    - a run with `finished` shows `ago`, and one without shows none;
    - a repo shows `checked … ago` only after `N running`;
  - `subtitleText` with and without `fetched`;
  - `duration()` keeps its output after the `seconds()` refactor;
  - `syncRows` refreshes `rowData` when only a raw time changes, including
    missing → value → missing and `serverDuration: 0`.
- `node tests/polling.cjs`: unchanged, passes.
- `tests/qml-smoke.py`, run in a `nixarchy-desktop` microVM only. New
  `esteps` on a fixture with `workerBusy=true`:
  - **Running job:** started 30 s ago. Wait for its delegate, capture
    `statusInfo.text` once, then retry, without resetting the baseline,
    until the text differs, or fail after 5 s. The polling request count
    and the `entries` array identity must be unchanged, which proves no
    poll or rebuild caused the change.
  - **Finished pipeline:** `finished` 8 s ago. The same capture-and-retry,
    from `just now` to a text containing `s ago`, allowing scheduler slack
    around the 10 s boundary.
  - **Stable view:** across those ticks, including one where the text width
    changes, `panel.current.key` and `listItem.contentY` stay the same.
  - a failed job with `failure_reason: "script_failure"`, whose info text
    contains `script failure`;
  - an MR pipeline whose subtitle starts with `!42`.

  Existing checks still pass, including the lint row's info (`1m 2s`, which
  is `row.info`, unchanged).
- **MicroVM screenshot** of these rows at 100% and 150% zoom, to check the
  elision.
- **Manual check after deploy:** on a real project, a failed job shows its
  reason and a finished pipeline shows "… ago".

## Review notes

Codex reviewed the draft read-only. It confirmed the `repo` variants, the
stage span, the ref search and the `shownFields` approach. Its findings,
which I checked in the code and folded in above:
- finished jobs were missing "… ago";
- `message` rows would lose their `queued` / `error` text;
- finished jobs without a finish time ignored GitLab's duration, so a
  `complete` flag now decides;
- the raw job field sources are now explicit, with one missing form per
  field;
- the info column's horizontal relayout on a tick is now described and
  checked;
- the smoke waits now capture once and retry, and do not rely on `held()`.
