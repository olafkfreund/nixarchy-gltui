# Spec: Show more than one GitLab host at once

## Design

One `Polling` state per host; the first host's state stays in the
panel's existing `polling` property, so every single-host code path and
smoke fixture keeps working. Rows carry their own host and raw ids, so
nothing parses a host out of a key. Row keys gain a host prefix only when
more than one host is configured.

### 1. Configuration (`Model.hostConfig`, `configure()`, `gitlab.py`)

The plugin entry gains an optional `hosts` list:

```json
{"id": "olafkfreund.gitlab-pipelines",
 "hosts": [
   {"host": "gitlab.com", "pinned": ["me/site"]},
   {"host": "gitlab.example.org", "actions": true, "projects": ["team/app"]}
 ]}
```

- Both the panel and `gitlab.py` read the **first** `plugins[]` entry
  with this id, as the panel does today (`gitlab.py actions_enabled`
  changes from "any entry" to "first entry").
- `hosts` absent or `[]`: today's single-host form (`host`, `actions`,
  `projects`, `pinned` at the top level), unchanged.
- `hosts` a non-empty array: it replaces the four top-level keys, which
  are ignored. Order of rules: (1) validate every item: an object with a
  `host` string matching today's pattern
  `^[A-Za-z0-9][A-Za-z0-9.-]*(:[0-9]{1,5})?$`; any invalid item, anywhere
  in the list, is a config error; (2) drop duplicates, compared
  case-insensitively on the whole `host` including any port, keeping the
  first; (3) keep the first 4. `actions` is on only when exactly `true`;
  `projects` and `pinned` are read per item as today's top-level keys.
- A config error (also `hosts` not an array) is shown like today's
  invalid-host error. It cancels any pending action, and `pump()` and
  `sendAction()` do nothing while `configError` is set; `adopt()` never
  replaces a config error with a polling error. `actions_enabled`
  returns `False` for every host.
- Ignored hosts (past 4) are logged once and named in a notice ("Ignored
  hosts: a, b; at most 4 are shown"), deferred to the next `open()` like
  `pinsError`.
- `Model.hostConfig(entry)` returns `{hosts: [{host, actions, projects,
  pinned}], ignored, error}`; `gitlab.py` gets a Python twin. A shared
  JSON fixture (`tests/host-config.json`: absent, empty, valid, invalid
  first or fifth item, duplicates, five distinct hosts, actions not
  `true`, a malformed first entry followed by a valid second) is checked
  by both `tests/model.cjs` and `tests/test_gitlab.py`.

### 2. Pollers and scheduling (`PipelinesPanel.qml`, `Polling.js`)

- Host 1's state is `polling`, as today. Hosts 2-4 live in `more`: an
  array of `{host, life, state}`. A helper list `pollers()` returns
  `[{host, life, state}]` for all hosts, and `setState(i, s)` writes back
  (host 1 through `polling`, keeping the reassignment in `adopt()` that
  notifies bindings). `life` comes from a panel-wide counter that only
  grows, so a removed and re-added host never reuses a lifetime.
  `Polling.js` stays single-host.
- **Single host**: `pump()` calls `Polling.next(polling, now)` exactly as
  today.
- **Several hosts**: the slot rotation moves to the panel. `pump()` keeps
  a panel slot with today's pattern
  (`interactive, interactive, interactive, active, background`) and the
  same fallback order. For that order it asks each host
  `Polling.choose(s, now, order)` — today's `next` up to the task pick,
  with the group order passed in — and takes the first host, round-robin
  from the one after the host served last, whose best task is in the
  earliest group. It then calls `Polling.commit(s, task, now)` on that
  host only. Background work on every host therefore gets every fifth
  turn, as on one host today, and no host can starve another.
  `Polling.next(s, now)` becomes `choose(s, now, today's order from
  s.slot)` + `commit`, byte-identical for one host.
- `choose` keeps `next`'s side effects that happen before the pick
  (`settle`, pruning `starts`, `seed`/`seedWatches`, `wakeAt`); only
  `commit` advances `slot`, `starts`, `requests`, `serial`,
  `lastRequest`, `lastStarted` and `flight`. After the `choose` round,
  `pump()` drains the events of **every** host.
- **Replies.** `requestInfo` records `host` and `life`. `receivePage`
  gives the reply to the poller with that host and life; a reply for a
  poller that is gone is dropped (`workerBusy` still cleared). A
  `requestInfo` without `host` (existing smoke fixtures) means host 1.
- **Open, close, view, refresh.** `open`, `close`, `view` and `manual`
  apply to every host. `r` refreshes the current row's host (all hosts
  when there is no row); `Shift + R` refreshes all hosts.
- **Selection.** `selectionChanged()` calls `Polling.select` on the
  current row's host with the row's raw `repo` and `run` and a local
  expansion map, and `Polling.select(s, "", "", local)` on every other
  host. The local map for host *h* is `shown` filtered to keys that start
  with `h + "|"`, with that prefix removed (one host: `shown` itself).
  `Polling.selectMr` gets the row's raw `mrKey`; `Polling.jump` gets the
  local map.

### 3. Rows and keys (`PipelinesModel.js`)

- `q` is `host + "|"` when more than one host is configured, else `""`.
  The panel tags each repo with `host` (always) and `q`, merges every
  host's `details` and `watched` with `q`-prefixed keys, and passes one
  `pinned` map keyed `q + path`.
- In `Model.rows`, `Model.autoOpen` and `jumpMr`: `repoKey = "repo:" + q
  + path`, `runKey = q + path + ":" + runId`, and the `details`,
  `watched` and `pinned` lookups use `q + path` (plus `":" + runId` for
  details and watches). All child keys derive from these, as today.
  `Model.merge`, `Model.selection` and `Model.syncRows` keep treating keys
  as opaque.
- Every row carries `host` (the real host, also with one host), plus its
  raw `repo`, `run`, `job` and, for merge requests, `mrKey`. Code that
  needs a raw id reads these fields; `current.key.slice(3)` in
  `jumpMr`, `selectionChanged` and `adopt` is replaced by `current.mrKey`.
- With several hosts a repo row shows a dimmed host label after the
  title, `repoMatches` also matches the host, and `accessibleName`
  appends "on <host>". Sorting stays global (pinned, then running first).
- `Model.mrRows(mrs, filter, now, host, selectedKey, q)` gains `q`; the
  panel concatenates each host's rows in host order. With several hosts,
  keys are `"mr:" + q + id!iid`, the host is in the label, the search
  text and the accessible name, and each truncated host has its own
  "N more on GitLab · <host>" row (key `"mr:more:" + host`). The MR
  header and empty label sum over hosts.
- **Host-count changes.** Going from one host to several or back changes
  every key. `configure()` then clears `expanded`, `searchCollapsed`,
  `viewState` and the cursor (the data stays); the README says so.
  Removing one of several hosts prunes its keys from those maps.

### 4. Links, traces, pins, watches, actions, notices

- **Links.** `Model.browsable(url, host)` compares the authority
  case-insensitively with the row's host, port included exactly; links,
  copies and "more" rows use the row's host. `t` traces pass
  `current.host`.
- **Pins.** `pinState[host] = {config, saved, loaded, loadFailed}`
  replaces the scalars `configPins`, `savedPins`, `pinsLoaded`,
  `pinsLoadFailed` and `pinsLoadHost`. Loads run one host at a time on
  `pinsLoad`, capture host and life, and are dropped if either changed.
  `sessionPins` (already keyed by host) survives a host's removal, so a
  re-added host shows its newest pins while a save is pending. A failed
  load still blocks that host's saves until a retry succeeds. Saves stay
  serialized on `pinsSave`. `p` uses the current row's host; the 10-pin
  cap is per host; `pinned.json` is unchanged.
- **Watches.** `Polling.watch(s, repo, run, now, others)` gains `others`,
  the number of watches on other hosts, and applies the cap to
  `others + own` at the point where it checks the cap today, so unwatch,
  missing and finished keep their precedence. The `watchNotice` footer
  text names the host with several hosts.
- **Actions.** `actionsFor(host)` replaces `actionsOn` (kept as
  `actionsFor(host 1)` for one host). `startAction` checks for a row
  before anything else; the actions-off hint and the `a c x n` keys in
  `listHint` follow the current row's host. The confirmation records
  `host` and `life`; `sendAction` drops it unless that host is still
  configured with actions on and its life unchanged, and uses that host's
  `cooldown`, `lastStarted` and `writeAt`. `finishAction` applies the
  cooldown and refresh to the poller with the captured host and life; if
  it is gone the result notice still shows (prefixed "on <host>:" as
  today), and nothing else is applied. Actions keep today's exception
  (one at a time, alongside a read). `Model.describe` appends
  "on <host>" with several hosts, and then `finishAction` adds no second
  prefix.
- **Re-adding a host** within a minute of removing it restores its
  `starts`, `lastStarted` and `writeAt` from `hostBudget[host]`, so
  neither reads nor actions exceed its limits.
- **Notices.** `drainEvents` passes each event's host to
  `Model.watchMessage`, whose texts add "on <host>" with several hosts
  (auth: "Run glab auth login --hostname <host>."). A removed host's
  watches end with a new event type `removed`: "N watches on <host>
  ended: the host was removed." Replacing the one host by another keeps
  today's `host` event and text.

### 5. Open from a repository (`Model.openFilter`, `applyOpen`)

- `Model.openFilter(payload, hosts)` accepts a host string (today's
  callers) or a list. It matches the payload's host by hostname
  (case-insensitive, port ignored as today). One configured match: it
  returns `{filter, host, notice: ""}`. Several configured hosts with that
  hostname (different ports): `host: ""`, no restriction. No match: the
  notice "Repository is on X; this panel shows Y, Z". A payload without
  `host` searches every host.
- With several hosts, `applyOpen` sets `openHost`, which `Model.rows` and
  `Model.autoOpen` apply before text matching. It is set together with
  the filter under a guard so `onFilterTextChanged` does not clear it; it
  is cleared by a user edit of the filter, by a later open without a
  match, and it is saved and restored with the projects view in
  `viewState`.

### 6. Errors, header, `status()`

- The error strip shows one line per host that is stopped or paused
  (paused derived from `cooldown`, not only `error`), prefixed with the
  host when there are several; `maximumLineCount` is the host count + 1.
  A host with no repos at all (configured `projects` and pins count as
  repos) shows only its line; a host that fails later keeps its rows.
- The header says "N projects on K hosts" with several hosts.
- `status()` with one host returns exactly today's object. With several
  hosts: panel-wide fields stay panel-wide (`opened`, `rows`,
  `repositories`, `checked`, `inFlight`, `filter`, `editing`, `selected`,
  `scrollY`, `confirm`, `actionBusy`, `view`, `statusPath`,
  `statusState`); `discoveryComplete` is true when every host is complete
  or stopped; `error` is the first host error, prefixed; `requests` and
  `mrs` are sums; `cooldown`, `lastStarted` and `updated` are the latest;
  `lastRequest` belongs to the latest start; `actionsOn` is true if any
  host has actions on; and `hosts` lists `{host, discoveryComplete,
  error, requests, cooldown, lastRequest, lastStarted, actionsOn, mrs}`.

### 7. Bar status (`Model.barStatus`, `bar-widget/BarModel.js`)

- With one host the file is byte-for-byte today's. With several it stays
  `version: 1` with every current field plus `hosts: [{host, state,
  running, failed, countsAt, cooldownUntil, reason}]`, each computed by
  today's single-host rules.
- Top level for several hosts: `running`/`failed` sum the hosts in state
  `ok` or `rate` that have counts; `state` is `stopped` for a config
  error, else `ok` if any host is `ok`, else `rate` if any host is paused,
  else `stopped` if any host is stopped, else `none`. `cooldownUntil` is
  the latest pause deadline when `state` is `rate` (so an old widget never
  turns `ok` while every host is still paused), else 0. `countsAt` is the
  oldest among the counted hosts; `host` is the first host plus " +N";
  `reason` is the first stopped host's reason prefixed with its host.
- The new widget, when `hosts` has more than one entry, re-derives each
  host's state (a `rate` host whose deadline has passed becomes `ok` or
  `none` as today), shows one tooltip line per host in every state,
  including `none` and `ok`, and sets its recheck to the earliest future
  per-host deadline.
- `Component.onDestruction` writes `state: "none"` and drops `hosts`.

## Alternatives rejected

- **One merged `Polling` state with host-qualified repo names**: the
  budget, cooldown, auth stop and errors would stay shared.
- **One worker per host in parallel**: removes the slow-host delay but
  adds processes and a new in-flight rule; the intent keeps one read at a
  time.
- **Strict urgency across hosts with round-robin only on ties**: one busy
  host could starve another's background discovery; the panel-level slot
  keeps today's 3-1-1 share.
- **Always prefixing keys, even with one host**: avoids the reset on a
  host-count change but alters every single-host key and dozens of smoke
  assertions.
- **Translating keys on a host-count change**: more code for a rare
  config edit; clearing expansion and cursor is enough.
- **Rows grouped under host headings**, **a plain list of host names**,
  **a version 2 status file** and **skipping invalid `hosts` items**: as
  in the intent's open questions.

## Risks

- **Single-host regressions** in a large `PipelinesPanel.qml` change.
  Mitigated by keeping host 1 in `polling`, `Polling.next` for one host,
  identical keys and texts, and running the existing smoke.
- **A slow or unreachable host** delays the others by up to one request
  timeout (25 s) per turn until its backoff grows; documented.
- **Same path and ids on two hosts** is the main mixing risk; the
  two-host smoke stage uses exactly that.
- **`gitlab.py` and QML disagreeing** on actions: the shared fixture.
- **Environment tokens**: `glab` may send `GITLAB_TOKEN` to several
  configured hosts; README warns.
- Hosts: p620 and razer after release; p510 untouched.
