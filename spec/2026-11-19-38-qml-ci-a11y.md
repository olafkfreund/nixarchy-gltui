# Spec: Run the QML smoke test in CI and add accessibility roles

## Design

### 1. A CI-only sub-flake runs the smoke test in a NixOS VM

A new flake in `ci/` (`ci/flake.nix`, `ci/flake.lock`, `ci/qml-smoke.nix`).
The root `flake.nix` does not change, so nixarchy's pin of this repo, its
lock and the runtime package stay as they are.

- **Inputs:**
  - `nixarchy`: `github:olafkfreund/nixarchy/<rev>`, pinned to the
    current `main` (`60073095`).
  - `nixpkgs` and `home-manager` follow nixarchy's own inputs, so the VM
    has the same Hyprland, quickshell and Qt that users run.
  - `gltui = { url = "path:.."; flake = false; }`: this checkout, so the
    PR's files are tested, not nixarchy's pin. Nix 2.35 accepts a parent
    path inside the same repo; it locks as `"path": ".."` with
    `"parent": []` (tried in a scratch repo).
- **Output:** `checks.x86_64-linux.qml-smoke`, a
  `pkgs.testers.runNixOSTest`. It is under the sub-flake's `checks`, so
  `nix flake check` in the root never starts it. CI and a local run use
  the same command:

  ```bash
  nix build ./ci#checks.x86_64-linux.qml-smoke -L
  ```

- **The VM node.** It is a focused copy of the parts of nixarchy's
  `tests/session.nix:129-221` the smoke test needs, without the RDP,
  sops, theme repo and app checks:
  - nixarchy's NixOS and Home Manager modules, `programs.nixarchy.enable`
    for user `omarchy` (uid 1000);
  - `WLR_RENDERER_ALLOW_SOFTWARE=1` and plymouth off, as in session.nix
    (`:184-190`);
  - SDDM autologin into the Nixarchy session:
    `services.displayManager.autoLogin = { enable = true; user = "omarchy"; }`
    and `services.displayManager.defaultSession = "omarchy"`, the
    `omarchy.desktop` session nixarchy registers
    (`nixarchy/modules/nixos.nix:139-147`, `:1539`). The user also gets
    password `omarchy`, so the test can fall back to typing it at the
    greeter as session.nix does if autologin is refused;
  - `python3` and `wl-clipboard` on the system path. Quickshell, its
    QtTest QML module (part of `qtdeclarative`, in quickshell's import
    path), fonts and `$OMARCHY_PATH` come from nixarchy's NixOS module
    (`nixarchy/modules/nixos.nix:1263`); the theme's `colors.toml`,
    fontconfig and `shell.toml` from its Home Manager module, as in the
    microVM;
  - 4 GiB of memory and 2 cores (a GitHub runner has 4 cores and 16 GiB).
- **The test script:**
  1. Wait for `display-manager.service`, then until `hyprctl monitors`
     works as `omarchy` (session.nix's `on_desktop` helper, `:561-564`).
  2. Readiness, each a named failure: `$OMARCHY_PATH/shell/Commons` and
     `Ui` exist in the session environment;
     `~/.local/state/omarchy/current/theme/colors.toml`,
     `~/.config/omarchy/shell.toml` and `~/.config/fontconfig` exist for
     `omarchy`. A missing QtTest shows as the smoke run's own
     "module QtTest is not installed" error, printed with `smoke.out`.
  3. `pkill -x hypridle`, then fail if `pgrep -x hypridle` still finds
     it, so the session cannot blank or lock during the run. A locked
     session makes every `keyClick` fail.
  4. Copy `${gltui}` to `/tmp/gltui`, owned by `omarchy` and writable,
     with a script `/tmp/run-smoke.sh`:
     `cd /tmp/gltui && python3 /tmp/gltui/tests/qml-smoke.py /tmp/gltui > /tmp/smoke.out 2>&1; echo $? > /tmp/smoke.rc`.
  5. Start it inside the session, so it gets the session's environment,
     with the pinned Hyprland's Lua dispatch, as session.nix does
     (`:518-522`):
     `hyprctl dispatch 'hl.dsp.exec_cmd("sh /tmp/run-smoke.sh")'`.
  6. Wait for `/tmp/smoke.rc` (10 minutes at most), print `smoke.out`,
     and fail unless the exit code is 0 and `QML_CHECKS_PASSED` appears
     twice, once per scenario.
- **CI:** a new `qml-smoke` job in `.github/workflows/check.yml`, next to
  `flake`, on the same triggers:
  - the KVM udev rule, reload, trigger and checks, copied whole from
    nixarchy's `build.yml:1704-1719`.
    A missing `/dev/kvm` fails the job instead of falling back to slow
    software emulation;
  - `cachix/install-nix-action` with `nixarchy.cachix.org` and
    `hyprland.cachix.org` and their public keys as extra substituters on
    the runner (`nixarchy/flake.nix:5-12`), pull only. Without the
    Hyprland cache the runner compiles Hyprland (`build.yml:1310-1315`);
  - the build command above, with `timeout-minutes: 45`.
- **The nixarchy pin in `ci/flake.lock`** moves by hand, when a new shell
  or Hyprland matters. The README says how.

### 2. The remaining direct calls become key presses

- The three `panel.toggleHelp()` calls (`tests/qml-smoke.py:1185`,
  `:1333`, `:1408`) become `tc.keyClick("?")` after `listFocus()`, as
  K7 already does (`:881`).
- The `move`/`expand` checks at `:1627-1669` are interleaved with
  fixture changes (polling state, `expanded`, `filterText`) and run
  before the panel opens (`:1670`). `open()` starts polling and moves
  focus through `Qt.callLater` (`PipelinesPanel.qml:123-131`). So the
  keyboard assertions move into their own step in the async stage list,
  after the open: the step sets its fixture again, waits until the list
  has active focus (`waitUntil`, as K8 does at `:906`), then presses
  `Down`, `Right` and `Left`, the keys E9 uses (`:689-696`). Fixture
  setup stays as direct calls; only the assertions that stand for a key
  press change.
- `panel.refresh(...)` (`:1725`, `:1773`) stays: it times an overlapping
  request.

### 3. Accessible roles and names

- **Names are built in `PipelinesModel.js`** by a new
  `accessibleName(row)`, so `tests/model.cjs` covers them without QML:
  - `title`, a kind word, then a status word, joined with ", ";
  - kind words: repo "project", run "pipeline", stage "stage",
    job "job", trigger "downstream pipeline". `more` and `message` rows
    give only their title;
  - status words come from `group(status)` (`PipelinesModel.js:75-88`):
    `success` → "passed", `allowed` → "failed, allowed", and running,
    failed, manual, scheduled, queued, skipped, canceled as they are.
    `neutral` and `unknown` give "no status";
  - "pinned" on a pinned project and "watched" on a watched pipeline,
    the same facts as the ★ and ◉ marks;
  - no times: they change every second, and a changing name is read again
    by a screen reader;
  - example: `"a/one, project, pinned, failed"`.
- **`PipelinesPanel.qml`:**
  - the row delegate (`:740`): `Accessible.role: Accessible.ListItem`,
    `Accessible.name: Model.accessibleName(modelData)`,
    `Accessible.selected: index === root.cursor`;
  - the list (`:731`): `Accessible.role: Accessible.List`,
    `Accessible.name: "GitLab pipelines"`;
  - the search box (`:665`): `Accessible.role: Accessible.EditableText`,
    `Accessible.name: "Search projects"`;
  - the footer hint (`:818`): `Accessible.role: Accessible.StaticText`,
    `Accessible.name: hint.text`, so a notice is read like the hint.
  - Nothing drawn and no key binding changes.
- **Smoke checks** (new stage, panel open): for one row of each kind, the
  delegate's `Accessible.role` and `Accessible.name` equal
  `Model.accessibleName` for that row; the selected row has
  `Accessible.selected` and no other row does; the search box, list and
  footer have their roles and names. The footer name follows a notice. A row's name changes when its status
  changes (a fake reply moves a pipeline from running to failed).
- **One manual check** in the microVM: list the panel with the ai-mirror
  accessibility tree and report what is exposed. This is evidence, not a
  pass/fail gate. Quickshell may need `QT_ACCESSIBILITY=1` and an AT-SPI
  bus to expose anything.

### 4. Docs and version

- `README.md`: a "Testing" note on the `ci/` command, and an
  "Accessibility" line on what the rows expose.
- `manifest.json`: 1.13.0.

## Alternatives rejected

- **A headless compositor straight on the runner (no VM).** Hyprland
  needs a logind seat; nixarchy found that running it under `su` fails
  with `CBackend::create() failed!` (`nixarchy/tests/session.nix:180-182`).
  It would also not have the Omarchy shell or theme.
- **`nixarchy` as an input of the root flake.** Nixarchy pins this repo,
  so its lock would gain a nested nixarchy with its 116 nodes, deeper on
  every bump. Breaking the cycle needs a change in nixarchy.
- **The test under the root flake's `checks`.** Every local
  `nix flake check` would boot a VM.
- **Running the test in nixarchy's CI instead.** It would only test what
  nixarchy pins, after the release, not this repo's pull requests.
- **Copying all of `session.nix`.** It tests RDP, secrets, apps and themes
  this panel does not use, at 6 GiB and four cores.
- **QML `TestCase` with `when: true`** in place of the custom stage
  runner: a rewrite of 1,800 lines for no new coverage.

## Risks

- **CI time and cache misses.** A closure not in the three caches builds
  on the runner. The 45-minute limit is a budget, not a measurement; the
  first run shows the real time. The job runs on every PR and push either
  way. If it cannot fit, that goes back to the intent, not into a
  narrower trigger.
- **Flaky first run.** The microVM smoke had one timeout on a fresh boot
  (#37). The readiness checks, waiting for `hyprctl monitors` and
  stopping `hypridle` should remove the cause. There is no retry: a
  failure fails the job, with `smoke.out` in the log.
- **The `path:..` input** needs Nix 2.26 or newer. `install-nix-action@v31`
  installs a newer one; the job prints `nix --version`.
- **The nixarchy pin goes stale.** The VM then tests against an older
  shell than users have. Only CI is affected, not users.
- **Hyprland's `dispatch` syntax changed** (nixarchy uses
  `hl.dsp.exec_cmd`, `session.nix:522`). The test uses the same form as
  the pinned nixarchy.
- **Accessibility properties are not read by anything** on today's
  desktop unless Qt accessibility is on. They are harmless if unused.
- Nothing changes on p620, razer or p510 until the 1.13.0 deploy, which
  ships only the QML and model changes.

## Verification

- `python3 -m unittest discover -s tests`, `node tests/model.cjs` (new
  `accessibleName` cases for each kind, status group, pinned and watched),
  `node tests/polling.cjs`, `nix build .#checks.x86_64-linux.plugin`.
- `nix build ./ci#checks.x86_64-linux.qml-smoke -L` passes locally on
  p620 (KVM, headless; nothing on the user's desktop) and prints both
  `QML_CHECKS_PASSED` lines.
- The same test fails when a smoke check is broken on purpose (one
  `check(false, ...)`), to show that CI catches it. That change is not
  committed.
- The `qml-smoke` job passes on the PR; the job log shows the KVM check
  and the run time.
- `nix flake check` at the root still does not start a VM.
- The microVM smoke run and the manual accessibility tree check, as in
  earlier releases.
