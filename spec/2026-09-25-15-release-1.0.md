# Spec: Port nixarchy-ghtui's pre-1.0 fixes, then release 1.0.0

## Design

Intent defaults apply (approved without answers): **one task, one PR per
fix**, then a release PR; **ghtui's limit** for unfinished pipelines.

Each fix copies the shipped ghtui change (ghtui PR #28, #35, #37) where the
code has the same shape, and adapts it where GitLab differs. Those places are
marked **GitLab:**.

### Fix A: helper failures (ghtui #24 / PR #28)

- `PipelinesModel.js` `reply(stdout, code, requestId)`: stderr is no longer a
  parameter. With empty stdout it returns `{requestId, errorType: "setup",
  error}`, where `error` is `"python3 not found"` for exit 127 and otherwise
  `"GitLab helper failed (exit N); see the shell log"`.
- `PipelinesPanel.qml`:
  - `property bool helperStarted`, reset in `pump()`.
  - `requestProc.onStarted` sets it. `onRunningChanged` calls
    `failedToStart()` when `!running && workerBusy && !helperStarted`, because
    in Quickshell 0.3.1 a failed start emits neither `started` nor `exited`.
  - `failedToStart()` feeds `Model.reply("", 127, id)` to `receivePage` and
    clears `workerBusy`.
  - `onExited` logs non-empty stderr with `console.warn` and passes only
    stdout and the code to `Model.reply`.
  - `receivePage` logs a rejected reply (first 300 characters) and uses
    `errorType: "setup"` with "…; see the shell log".
- `Polling.js` `complete`:
  - The reply-shape check from #10 also requires every list item to be an
    object.
  - A bad shape becomes `errorType: "setup"` instead of `"network"`.
  - `setup` stops polling until a manual refresh, as `auth` does
    (`s.auth = true`, with ghtui's `ponytail:` note on the name).
  - **This revises #10's decision**, which retried bad data as `network`. A
    helper that returns garbage is a bug or a broken install, not a transient
    fault. Retrying it only hides the cause.
- `gitlab.py`:
  - `read_page` catches `FileNotFoundError` (only `Popen(["glab", …])` raises
    it) and returns `errorType: "setup"`, `error: "Install glab (GitLab CLI)"`.
  - `main()` adds `errorType` (`network` for a deadline, timeout or `OSError`,
    otherwise `setup`) and the request's `requestId`, when that is a positive
    int, to its error JSON.

### Fix B: large projects (ghtui #30 / PR #35)

- `gitlab.py`: a `summary` task for an unfinished status, or an `activity`
  task, reads **one page of 100** and never sets `nextPage`. Only `catalogue`
  and `jobs` still paginate. It adds `result["total"]`, taken from the
  response header:
  - **GitLab:** there is no `total_count` field; the count is the `X-Total`
    header.
  - **GitLab:** above 10,000 results GitLab leaves `X-Total` out. Then
    `total` is `-1`, meaning "more than one page, count unknown" when
    `X-Next-Page` is set, and the page length when it isn't.
  - A present but malformed `X-Total` raises `ValueError`, the same as
    ghtui's invalid-total check.
- `Polling.js`: port `kept()`, `activity(s,r,items,now,total)` (a partial
  page drops only runs nobody is looking at), `r.active` from `total`, and
  the per-status hidden counts: `t.hidden` → `r.hidden` at the end of a
  summary, and `r.hidden.running` from activity.
  - **GitLab:** the in-progress phase is `running`, not `in_progress`.
    `total = -1` is stored as `-1`.
- `PipelinesModel.js` `rows()`: an expanded project gets one "more" row
  before its first completed pipeline.
  - Its title lists each unfinished status with hidden pipelines: `+N more
    running · +N more pending · …`, using "about N" above 1000 and
    `+more <status>` for `-1`.
  - **GitLab:** the statuses are `running`, `pending`, `created`,
    `waiting_for_resource` and `preparing`. The subtitle is `o opens GitLab`,
    and the url is `<project url>/-/pipelines`.
- `PipelinesModel.js` `syncRows`: port ghtui's linear algorithm. Remove
  unwanted keys first, then insert or move by key. `setProperty` only when a
  field in `shownFields` (`title`, `subtitle`, `status`, `info`) changed, with
  ghtui's `ponytail:` note. The delegate reads no other changeable fields
  (check this when implementing).

### Fix C: untrusted text and runtime deps (ghtui #32 / PR #37)

- `gitlab.py`:
  - Add `JOINERS = "‌‍"` and `plain(value)`: line breaks and tabs
    become spaces, and other `Cc`/`Cf` characters are removed, except the
    joiners.
  - Apply it to project `description`, pipeline `name` and `head_branch`
    (the `ref`), and job `name` and `stage`.
  - **GitLab:** `display_title` is the first 8 characters of the commit SHA,
    which is already hex, so it needs no filtering.
- `PipelinesModel.js` `browsable(url, host)`: true only for
  `https://<host>/` followed by one or more characters that are neither
  whitespace nor `Cc` (`\x00-\x1f\x7f-\x9f`).
  - **GitLab:** the host is configurable, so it's a parameter, escaped for
    the regex.
  - `openBrowser()` uses it in place of today's prefix check.
- `flake.nix`: `passthru.runtimeDeps = [ pkgs.glab pkgs.python3
  pkgs.xdg-utils ]`, with ghtui's comment that they're found on PATH at run
  time.

### Release

- A PR titled `chore: release 1.0.0` that only sets `manifest.json` `version`
  to `1.0.0`.
- After it merges: tag `v1.0.0` on the merge commit and publish a GitHub
  release. The notes use ghtui's shape: Highlights (#6/#12 sizing, #10
  hardening and CI, and fixes A–C), Maintenance, and Upgrade notes (text now
  at theme size, fixed 900×680 card).
- A nixarchy PR bumping the `nixarchy-gltui` pin to the release commit.

### Tests (mirroring ghtui's tests for each fix)

- **A:**
  - Node: a list with a non-object item → `setup` error, and polling stops
    until `manual()`.
  - Model: `reply("", 127, id)` → "python3 not found", and a non-127 exit
    names the code, with no stderr text.
  - Python: `FileNotFoundError` from `request` → `setup` / "Install glab";
    `main()` error JSON carries `errorType` and `requestId`.
  - QML smoke: a helper path that doesn't exist makes `failedToStart` set a
    `setup` error and leaves `workerBusy` false.
- **B:**
  - Python: a running summary reads one page and sets `total` from
    `X-Total`; a missing `X-Total` with `X-Next-Page` gives `-1`; a malformed
    `X-Total` gives `network`.
  - Node: `total > items` gives `r.hidden`, a dropped run nobody looks at
    leaves `r.runs`, and a kept run stays.
  - Model: the "more" row's text and position, and "about N" / `+more`.
    `syncRows` on 3,000 rows is linear: the test counts `model.get` calls and
    stays within a fixed multiple of n.
- **C:**
  - Python: `plain` strips U+202E and U+0007, keeps ZWJ, and turns `\n` and
    `\t` into spaces.
  - Model: `browsable` accepts `https://gitlab.com/g/p/-/pipelines/1` and
    rejects another host, a control character, whitespace and
    `https://gitlab.com.evil/…`.
  - `nix eval .#packages.x86_64-linux.default.runtimeDeps` lists the three
    packages.

## Alternatives rejected

- **Fetch all unfinished pipelines, as gltui does today.** That's the
  quadratic path ghtui removed.
- **GitLab's keyset pagination to get exact counts past 10,000.** It needs a
  different endpoint shape. `-1` / "+more" covers the case, and `o` opens
  the full list on GitLab.
- **Keep #10's retry-as-network for bad data.** It hides a broken install
  behind endless retries. ghtui chose to stop and say so.
- **Release 1.0.0 before the fixes.** The owner chose to port first.

## Risks

- **The "more" row depends on `X-Total`.** If a proxy strips the header,
  counts fall back to `-1` ("+more"), which is still correct, just less
  specific.
- **Stopping on `setup` needs a manual refresh** after, for example,
  installing glab. The error text says what to do, and `r` resumes polling.
- **Fix B changes `Polling.js` summaries.** The existing budget test in
  `tests/polling.cjs` (requests per 30 minutes) must still beat its baseline.
- **Three PRs touch the same files.** Merge them in order A → B → C, each
  rebased on the previous one.

## Verification

- Each fix PR: `nix flake check`, `python3 tests/qml-smoke.py` and `./result`
  → `QML_CHECKS_PASSED`, `omarchy plugin validate` exit 0, and the new tests
  fail on the code before the fix (as in #10).
- Release: `jq -r .version manifest.json` → `1.0.0`; `gh release view v1.0.0`
  exists; the nixarchy pin equals the release commit and nixarchy's
  `options`, `menu-verbs` and `plugin` checks pass.
- Live, with the user's go-ahead and a claim on the bus: the panel on razer
  lists projects, and a project with more than 100 pending pipelines (if one
  exists) shows the "more" row.
