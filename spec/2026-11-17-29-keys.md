# Spec: Help, copy, jump, close and next-failure keys

## Design

### 1. Helper: the full SHA (`gitlab.py`)

`pipeline(row)` (`gitlab.py:146-156`) adds one field:

- `sha`: `row["sha"]` when it is a string matching `[0-9a-f]{7,64}`,
  otherwise `""`.

`display_title` (the 8-character short SHA) is unchanged. Single-pipeline
lookups go through the same `pipeline()`, so they carry `sha` too.
`Polling.js` stores run objects as they come and needs no change.

### 2. Model (`PipelinesModel.js`)

- **Rows:** a `run` row gets `sha: run.sha || ""`. Its `stage` and `job`
  rows get the same `sha`, so `Y` works anywhere inside a pipeline. `repo`,
  `more` and `message` rows have no `sha` field. `sha` is added to
  `shownFields`, with `""` as its only missing form.
- **`nextFailure(rows, cursor)`:** a pure function. It returns the index of
  the first row after `cursor` whose `kind` is `run`, `stage` or `job` and
  whose `status` is exactly `"failed"`, wrapping to the start and ending
  back at `cursor`. The cursor's own row is checked last, so pressing `e` on
  the only failure keeps it selected. It returns `-1` when no such row
  exists.
  - Today's statuses already mean the right thing: a job that failed with
    `allow_failure` has status `allowed to fail` (`PipelinesModel.js:207`),
    a stage with only such failures is `success` (`:48,51`), and project and
    loading errors are `error` or `unavailable`.
- **`copyText(row, what)`:** a pure function, `what` being `"url"` or
  `"sha"`. It returns `{text, label}` or `{text: "", label: <message>}`:

  | Case | Result |
  |---|---|
  | `url`, row has a `url` | `{text: url, label: "Copied URL"}` |
  | `url`, no `url` (message rows) | `{text: "", label: "Nothing to copy"}` |
  | `sha`, row has a `sha` | `{text: sha, label: "Copied " + sha.slice(0, 8)}` |
  | `sha`, no `sha` | `{text: "", label: "No commit for this row"}` |
  | no row | `{text: "", label: "Nothing to copy"}` |

### 3. Panel (`PipelinesPanel.qml`)

**Key handling** in the list handler (`:331-351`). After the zoom check
(`:332`), as today:

1. **Help open:** while `helpOpen` is true, only these keys act:
   - `?`, Esc and `q` close help;
   - ↑ / ↓ / `j` / `k` and Page Up / Down scroll it.

   Every other key is accepted and does nothing.
2. **New keys:** these only act when Ctrl, Alt and Super are all released
   (`!(event.modifiers & (Qt.ControlModifier | Qt.AltModifier | Qt.MetaModifier))`).

   | Key | Match | Action |
   |---|---|---|
   | `?` | `event.text === "?"` | `helpOpen = true` |
   | `y` | `Qt.Key_Y`, no Shift | `copy("url")` |
   | `Y` | `Qt.Key_Y` with Shift | `copy("sha")` |
   | `g` | `Qt.Key_G`, no Shift | `move(-entries.length)`, as Home |
   | `G` | `Qt.Key_G` with Shift | `move(entries.length)`, as End |
   | `q` | `Qt.Key_Q`, no Shift | `close()` |
   | `e` | `Qt.Key_E`, no Shift | `nextFailure()` |

   - `?` is matched by its text, so the layout does not matter.
   - It is checked before the `/` branch, because on some layouts `?` and
     `/` share a key.

The search field's handler (`:373-389`) is unchanged: it only takes ↑ / ↓,
Enter, Esc and Tab. Every other key, including `?`, `q`, `g`, `e` and `y`,
types into the box.

**`nextFailure()`:**
- `i = Model.nextFailure(entries, cursor)`.
- If `i >= 0`: `cursor = i`, `positionViewAtIndex(i, ListView.Contain)`,
  `selectionChanged(false)`, as `move()` does (`:133-137`).
- Otherwise: `notify("No failures in the list")`.

**Copy:**
- `copy(what)` calls `Model.copyText(current, what)`.
  - **Empty text:** `notify(label)`.
  - **Otherwise:** it starts `copyProc` with
    `command: copyCommand.concat([text])`, where
    `property var copyCommand: ["wl-copy", "--"]` is also a test hook.
  - The text is its own argument, never passed through a shell.
- `copyProc` follows the helper's process pattern (`:290-299`):
  - `onStarted` sets `copyStarted`;
  - `onExited(code)` notifies the label on code 0, otherwise
    `Copy failed`;
  - `onRunningChanged` notifies `Copy failed` when the process stops without
    having started (Quickshell 0.3.1 emits nothing else for a missing
    binary).
- **A second copy while one is running:** it is ignored, with no notice.
  `wl-copy` forks and returns at once, so this window is short.

**Notice:**
- `property string notice`.
- `notify(text)` sets it and restarts `noticeTimer` (2000 ms), which clears
  it.
- Footer text (`:518`):

  ```
  root.notice || root.cooldownText ||
      (root.filtering ? searchHint : listHint)
  ```

  - `searchHint`: `↑↓ select  Enter open  Tab navigate  Esc clear`.
  - `listHint`:
    `↑↓ move  ←→ expand  / search  e failure  y/Y copy  o GitLab  ? help  q close`.
    `r`, `R` and zoom move to the help overlay. Their full list stays
    there, in the README and in the keybindings menu.

**Help overlay:**
- A `Rectangle` filling the `keys` item (`:323`), above the column. It has
  the menu background and is visible while `helpOpen`.
- It holds a `Flickable` with a plain `Text`, using the same font and zoom as
  the rows (`root.zf(Style.font.body)`).
- **Content:** the output of `keybindings.sh --print`, read once by a
  `Process` on the first open and cached in `property string helpText`.
  - This keeps a single key list: the keybindings menu, the overlay and
    the tests share it.
  - While it loads, or if it fails, the overlay shows
    `Help unavailable — see the README`.
- **Scrolling:** ↑ / ↓ / `j` / `k` scroll by one line height, and Page Up /
  Down by the visible height, clamped to the content.
- A closing line, `? or Esc to close`, sits at the top of the overlay.

**Close** (`:93-97`) also sets `helpOpen = false` and `notice = ""` and
stops `noticeTimer`, so the panel reopens in its normal state. Opening help
does not change the selection, the filter or the expansion.

**Test hooks:** `helpItem`, `footerHint` (an alias of `hint.text`),
`copyCommand`, `notice`, `helpOpen`.

### 4. Key list and docs

- **`keybindings.sh`** adds these lines, after `o → …`:
  - `y → Copy the selected row's GitLab URL`
  - `Shift + Y → Copy the pipeline's commit SHA`
  - `g / G → First or last row`
  - `e → Next failed pipeline, stage or job`
  - `? → Show or hide this help in the panel`
  - `q → Close the panel`
- **`README.md`:**
  - the Keyboard table gains the same rows;
  - Requirements (`:11`) names `wl-copy` (wl-clipboard) for the copy keys;
  - one sentence says that `e` only looks at rows already shown.

## Alternatives rejected

- **A second, hard-coded key list in QML.** It would drift from
  `keybindings.sh`.
- **Help through the existing keybindings menu.** It hides the panel and
  opens a second window (`keybindings.sh:33`); rejected in the intent.
- **Quickshell's own clipboard API.** Its availability and behaviour on this
  Quickshell version from a layer surface are unverified. `wl-copy` is what
  the Omarchy shell's own panels use.
- **`e` expanding collapsed pipelines.** It would fetch or change the view
  behind the user's back; rejected in the intent.
- **`Y` on a project row copying the latest pipeline's SHA.** The copied
  SHA would not match the selected row; rejected in the intent.

## Risks

- **`?` across layouts.** `event.text` is what the layout produced. A layout
  where `?` needs AltGr carries `MetaModifier` or `AltModifier` on some
  setups and would be refused by the modifier rule. Not verified; the
  smoke test checks Shift + `/` on US.
- **`wl-copy` from a layer surface.** `wl-copy` takes the selection with its
  own Wayland connection, not the panel's surface, so it does not depend on
  the panel's focus. The microVM smoke test confirms it with `wl-paste`.
- **Footer width:** the list hint is longer. It elides at the right, as
  today. Checked in the microVM screenshot at 100% and 150%.
- **Hosts:** a panel, helper and docs change, released through the usual
  chain to p620 and razer. p510 stays on 1.0.0.

## Verification

- `python3 -m unittest discover -s tests`: new `test_gitlab.py` cases:
  - `pipeline()` passes a valid `sha` through;
  - a missing, non-string or non-hex `sha` becomes `""`;
  - `display_title` is unchanged.
- `node tests/model.cjs`:
  - `nextFailure`: finds the next failure; wraps; skips `allowed to fail`,
    `error`, `unavailable`, `repo` and `message` rows; returns the cursor's
    own row when it is the only failure; returns `-1` with none and on an
    empty list;
  - `copyText`: every row of the table above;
  - rows: the `run`, `stage` and `job` rows carry the run's `sha`;
  - `syncRows` refreshes when only `sha` changes.
- `tests/qml-smoke.py`, run in a `nixarchy-desktop` microVM only. New
  `esteps` on a fixture with `workerBusy=true` and a failed job and
  pipeline:
  - `g` / `G` select the first and last row; Home and End still do;
  - `e` steps through the failures in order and wraps, skips the
    allowed-to-fail lint job, and with no failure leaves the cursor and
    sets `notice`;
  - `y` on a pipeline row: the real `wl-copy`, then `wl-paste -n` (from a
    `Process` in the test) returns the URL, and `notice` is `Copied URL`;
  - `Y` on a job row copies its pipeline's SHA; on a project row it sets
    `No commit for this row` and the clipboard is unchanged;
  - with `copyCommand` set to a missing binary, `notice` becomes
    `Copy failed`;
  - `?` (Shift + `/`) opens help: `helpItem` is visible, and its text
    contains `Next failed pipeline`. `j` scrolls it, Ctrl + `=` still zooms,

  - `q` closes the panel with a filter active; reopening shows no help and

  - in the search box, typing `q?gye` puts `q?gye` into the filter, the
