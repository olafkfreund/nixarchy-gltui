# Spec: Harden edge cases, add package metadata and CI

## Design

The intent was approved without answering its questions, so its defaults
apply: **no host allow-list** (question 1) and **CI on GitHub Actions**,
x86_64-linux only (question 2).

1. **Cap the rate-limit cooldown** (`Polling.js` `complete`). Change
   `s.cooldown=Math.max(s.cooldown,deadline);` to
   `s.cooldown=Math.max(s.cooldown,Math.min(deadline,now+3600000));`
   (`ponytail:` comment: one hour). `s.cooldown` is only set here, so it can
   never exceed one hour from the last reply. Tasks retried on a rate limit are
   due at `s.cooldown`, so they follow the cap.
2. **Check reply data before use** (`Polling.js` `complete`). Right after
   `if (!t) return false;`, if the reply has no error and its `data` has the
   wrong shape (not a plain object for `run`, not an array for every other
   kind), replace the reply with
   `{error:"GitLab helper returned invalid data", errorType:"network"}`. It
   then goes through the existing network-error path: message shown, backoff,
   retry from page one. This matches what `receivePage` already does for
   unparseable JSON.
3. **Read HTTP replies strictly** (`gitlab.py`).
   - `http_reply`: read another header block only while the last status was
     1xx (`while text.startswith("HTTP/") and (status is None or status < 200)`).
     A body that starts with `HTTP/` stays body.
   - `read_page`: treat 3xx as an error. The decode fallback becomes
     `if status < 300: raise`, and the error branch `if status >= 300 or code:`
     gets `elif 300 <= status < 400:` →
     `errorType="network", error="GitLab redirected the request; the project may have moved"`,
     placed after the auth and permission cases.
4. **`menu.py` `session_tree`**: skip entries that aren't dicts with a string
   `config_path`. Malformed output then fails the existing "Expected one
   running Omarchy shell" check, and `main` prints its normal one-line
   `RuntimeError` message.
5. **Package `meta`** (`flake.nix`): the `runCommand` attribute set gets
   `meta = { description = "GitLab Pipelines panel for the Omarchy shell"; homepage = "https://github.com/olafkfreund/nixarchy-gltui"; license = nixpkgs.lib.licenses.mit; platforms = nixpkgs.lib.platforms.linux; };`.
6. **CI**: `.github/workflows/check.yml`, on `pull_request` and `push` to
   `main`: `ubuntu-latest`, `actions/checkout@v7`,
   `cachix/install-nix-action@v31`, then `nix flake check -L`. The check
   already runs offline in the sandbox (Python, Node, and the qml-smoke
   negative path).

**Tests:**

- `tests/polling.cjs`:
  - a rate reply with `retryAt` a year ahead leaves `cooldown` at
    `now + 3600000`;
  - a `summary` reply with `data:null` and a `run` reply with `data:[]` each
    set `s.error` to the invalid-data message and schedule a retry, without
    throwing.
- `tests/test_gitlab.py`:
  - `http_reply` on `"HTTP/2 200\n\nHTTP/1.1 500 x\n\n[]"` returns status 200
    and the body `"HTTP/1.1 500 x\n\n[]"`; a `100 Continue` block followed by
    a 200 still parses as 200;
  - a 301 reply maps to `errorType` `network` with the redirect message;
  - `main()` with `read_page` patched to raise `DeadlineExceeded` prints
    `{"error": "GitLab request timed out"}` and returns 1.
- `tests/test_menu.py`: `session_tree([{}])`, `([{"config_path": None}])`
  and `(["x"])` raise `RuntimeError`.
- `tests/qml-smoke.py`: before the valid `configure(...)` call, call
  `panel.configure` with host `"bad host"` and check that `panel.error` starts
  with `"Configuration: invalid host"` and `panel.host` is unchanged.

## Alternatives rejected

- **Host allow-list from glab's config** (question 1 default). It protects
  only against someone who can already edit the user's config, and it ties the
  plugin to glab's config file format.
- **Validate data in `receivePage` (QML) instead of `Polling.js`.** The kind
  is known in `Polling.complete`, and the Node test can reach it there without
  a Wayland session.
- **Smoke tests for `openBrowser` and a garbled reply.** `openBrowser` calls
  `Quickshell.execDetached`, which the smoke test can't observe without adding
  a test hook to production code. A garbled reply ends in the same
  `Polling.complete` error path that the new Node test covers, and the JSON
  parse catch in `receivePage` is two lines.
- **Follow 3xx redirects in the helper.** glab (Go's HTTP client) already
  follows them for normal redirects. A 3xx that reaches us is unusual, so
  showing it is safer than guessing.
- **Nix build caching (Cachix, magic-nix-cache) in CI.** The check builds in
  seconds from nixpkgs' binary cache; add caching when CI time matters.

## Risks

- The one-hour cap ignores a genuine longer server limit. It still retries,
  hits 429 again, and backs off, so the cost is one request an hour.
- Stricter `http_reply` rejects a reply glab prints with several non-1xx
  header blocks. glab prints one block per final response, so this isn't
  expected. A test covers the 1xx case.
- The CI action versions age. Dependabot isn't in scope; bump them by hand.

- `node tests/polling.cjs`, `node tests/model.cjs` and

- `python3 tests/qml-smoke.py` and `./result` print `QML_CHECKS_PASSED`.
