# Spec: Show the latest pipeline status on each project row

## Design

One change in `PipelinesModel.js` `rows()` (the repo row at `:216-221`) and
`infoText()` (`:154-158`). No scheduler, helper or QML change: the row's
`status` already drives the icon and colour (`PipelinesPanel.qml:752-758`).

1. **Latest known finished pipeline.** A new helper
   `latest(runs)` returns the run with the highest `id` among
   `runs` with `status === "completed"` and no `awaitingFinal`, or `null`.
   "Any ref" is implicit: `r.runs` holds every ref the panel has seen.
2. **Row status**, in order of precedence:
   `repo.error` → `"error"`; `active > 0` → `"running"`; a latest run →
   `state(run)` (its `conclusion`: `success`, `failed`, `canceled`,
   `skipped`, `manual`, …, mapped to icons by `icon()`); else `"neutral"`.
3. **Row info.** The existing `info` string is kept (`N running`,
   `not checked`, `archived`, `disabled`, `unavailable`) with one new value:
   `"no pipelines"` when the project's summary has finished
   (`repo.summaryAt`) and `repo.runs` is empty. The row gains
   `last: {status, at}` (`at` = `completed_at || updated_at`) when a latest
   run exists and the project is not in error.
   `infoText()` for a repo row becomes:
   `info` + (`last` ? ` · last <status> <ago>`) + (running-suffix rule
   unchanged: ` · checked <ago>` only when `info` ends in `running`).
   Example: `0 running · last failed 2h ago · checked 3m ago`.
   With an unparseable `at`, the age is dropped: `· last failed`.
4. **Sort order** (`rows()` `:213`) is unchanged.
5. **Docs.** README project-row text (`README.md:127`, `:217`) describes the
   icon and the `last …` text, including that it is the latest the panel
   has seen (selected projects, or pipelines seen running), and that
   never-selected idle projects stay `·`. `manifest.json` → 1.11.0.

## Alternatives rejected

- **Fetch the newest pipeline per background check** (`per_page=1`): about
  +155 requests per 30 minutes (626), over #35's 500 target.
- **One initial fetch per project:** +136 (607), over the target.
- **GraphQL sweep with the catalogue:** cheap in requests but a new API
  path (POST, cursors, GraphQL errors) with complexity limits not
  verifiable here. Left for a follow-up issue.
- **Replace the running check with a latest-N fetch:** loses the running
  total and older concurrent running pipelines (`Polling.js:285-286`).
- **Sort failed projects higher:** not asked for in the issue.

## Risks

- **Stale result.** A cached success can hide a newer failure that started
  and finished between idle checks. Mitigated by the `last <status> <ago>`
  text showing the age; documented in the README.
- **Status of an older running vs newer finished pipeline:** running wins,
  by design (intent).
- No request, scheduling or layout change, so no host-specific risk. Rows
  with the new info text are a little longer; `info` already elides at 35%
  of the width (`PipelinesPanel.qml:785`).
