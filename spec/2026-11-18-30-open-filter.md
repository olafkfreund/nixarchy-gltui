# Spec: Open the panel filtered to one project

## Design

### 1. Model: a pure payload parser (`PipelinesModel.js`)

`openFilter(payload, panelHost)` returns `{filter, notice}`.
- `filter` is the cleaned text, or `null` when the open must not change the
  filter.
- `notice` is a footer message, or `""`.

ES5, no exceptions escape.

1. **The value:**
   - A string is parsed with `JSON.parse` inside `try`. Anything that fails
     to parse gives `{filter: null, notice: ""}`.
   - A non-string payload is used as it is, so a caller that hands
     `open()` an object directly also works.
2. **Object check:** the value must be a non-null, non-array object.
   Otherwise the result is `{null, ""}`.
3. **`filter`:**
   - It must be a string.
   - Control characters, C0 and C1 (`[\u0000-\u001f\u007f-\u009f]`), are
     removed, then it is trimmed.
   - It must then be between 1 and 200 characters. Otherwise the result is
     `{null, ""}`. A longer filter is rejected, not truncated.
4. **`host`, when present:**
   - It must be a non-empty string, or the result is `{null, ""}`.
   - It is compared case-insensitively with `panelHost`, without the
     panel's optional `:port`. The panel's host may carry a port
     (`PipelinesPanel.qml:212`), and remotes never send one.
   - **On a mismatch:**
     `{filter: null, notice: "Repository is on " + host + "; this panel shows " + panelHost}`.
     The host text is capped at 100 characters, and its control characters
     are removed, as for `filter`.
5. **Otherwise:** `{filter: <cleaned>, notice: ""}`.

`"{}"`, the payload every caller sends today, gives `{null, ""}`.

### 2. Panel: apply it in `open()` (`PipelinesPanel.qml:93-104`)

The new lines go after `opened = true` and before
`selectionChanged(true)`, so that the first selection the poller sees is
already the filtered one:

```qml
if (configured) applyOpen(payload)
else pendingOpen = pendingOpen.concat([payload])
```

```qml
function applyOpen(payload) {
    var request = Model.openFilter(payload, host)
    if (request.filter !== null) {
        helpOpen = false
        notice = ""; noticeTimer.stop()      // an older host warning must not linger
        if (filterText === request.filter) { rebuild(true); selectionChanged(false) }
        else filterText = request.filter     // onFilterTextChanged rebuilds and selects row 0
    }
    if (request.notice) notify(request.notice)
}
```

- **The host must be known first.** `host` comes from `shell.json` through
  a `FileView` (`:342-348`, `configure()` at `:207-224`). Until that has
  loaded, `host` is the default `gitlab.com`.
  - `property bool configured: false`, set to `true` at the end of
    `configure()`, including when it fails, and in the `FileView`'s
    `onLoadFailed`, because with no `shell.json` the default host is the
    real one.
  - Until then, `open()` queues payloads in `pendingOpen`.
    `configure()` applies the queue in order and clears it, the first time
    it sets `configured`.
  - A `"{}"` payload in the queue applies as a no-op, so ordering stays
    simple.

- **Focus:** `open()` already ends with
  `Qt.callLater(function() { keys.forceActiveFocus() })` (`:103`). That
  takes focus from the search box when it had it, so navigation keys work
  at once.
- **Unchanged:**
  - search, the #27 auto-open, `expanded` and `searchCollapsed`;
  - a valid filter only sets the text, as typing it would. The
    `onFilterTextChanged` handler (`:53-57`) resets `searchCollapsed`,
    rebuilds and selects the first row;
  - `toggle()` (`:114`) still sends `"{}"`.

### 3. `menu.py open [FILTER]`

- **Usage:** `main()` accepts `open` with zero or one more arguments. The
  usage line becomes `menu.py [keys|toggle|register|open [FILTER]]`.
- **With `FILTER`:** the payload is `{"filter": FILTER}`.
- **Without it:**
  - `git remote get-url origin` runs in the current directory
    (`subprocess.run`, `capture_output`, `text`, `timeout=5`, `check=False`).
  - On exit 0, `remote(url)` (below) parses the output. A missing `git`
    (`OSError`) or a timeout (`subprocess.TimeoutExpired`) counts as no
    remote.
  - A parsed remote gives `{"filter": path, "host": host}`.
  - Otherwise the payload is `{}`, and one line goes to stderr: `no Git
    origin remote here` or `unsupported Git remote: <url>`. The exit code
    is 0, and the panel still opens.
- **The command:**
  `["omarchy-shell", "shell", "summon", "olafkfreund.gitlab-pipelines", json.dumps(payload)]`,
  started through the existing `os.execvp` path after `session_tree()`.
  The payload is one argument; no shell is involved.
- **`remote(url)`** returns `(host, path)` or `None`. It strips the
  surrounding whitespace first.

  | Form | Rule |
  |---|---|
  | `ssh://`, `http://`, `https://` | `urllib.parse.urlsplit`. The host is `.hostname`, already lower-case, so the user and port are dropped. The path is `.path`. Any other scheme gives `None`. |
  | SCP-style `[user@]host:path` | `^(?:[^@/\s]+@)?([^@/:\s]+):([^/].*)$`. The host is lower-cased. A path starting with `/` is a local path, so it gives `None`. |
  | Anything else (a local path, `file://`) | `None`. |

  - **Path:**
    1. Strip leading and trailing `/`.
    2. Remove one trailing `.git`.
    3. Split on `/`.
  - **Rejected paths:**
    - the path must have at least two segments, none of them empty, `.`
      or `..`;
    - it must contain no whitespace and no `%`. Percent-encoded paths are
      unsupported: the panel searches literal text, so `g%72oup` would
      never match.
  - **Rejected hosts:**
    - a missing host;
    - a bracketed (IPv6) host in SCP form. The panel's host setting
      accepts no IPv6 either (`PipelinesPanel.qml:212`).
  - **Ports:** a port needs `ssh://`. In SCP form, `host:2222/g/p` reads
    `2222` as part of the path, as Git itself does.
  - **Parse errors:** `remote()` catches `ValueError` from `urlsplit` (for
    example `https://[broken/g/p`) and returns `None`, so an unsupported
    remote still opens the panel.
  - The panel cleans and caps the filter again. `menu.py` does not need to
    trust its own parsing.

### 4. Docs

- **`README.md`:** a short section, "Open on the current repository":
  - the command, and an example alias:
    ```bash
    alias glp='python3 ~/.config/omarchy/plugins/olafkfreund.gitlab-pipelines/menu.py open'
    ```
  - the raw `omarchy-shell shell summon … '{"filter":"group/project"}'`
    form for scripts;
  - one sentence each on the host check and on `origin` only.
- **The help key list** (`keybindings.sh`) is for panel keys, so it is
  unchanged.

## Alternatives rejected

- **Parsing the payload in QML only:** Node could not test it.
- **Ignoring the host:** this was the intent's first draft. A GitHub
  checkout could show a same-named GitLab project.
- **Truncating long filters:** a cut filter can match the wrong project;
  rejecting it leaves the filter unchanged.
- **Expanding the matched project:** deferred by the intent (question 3).
- **A separate shell script for `open`:** `menu.py` already finds the
  running shell tree (`session_tree`) and is what the keybindings call.

## Risks

- **Host changes later:** payloads wait for the first configuration
  (above). If the user later edits `shell.json` to another host, a filter
  already set stays, as a typed search does today.
- **`onLoadFailed`:** this relies on Quickshell's `FileView` emitting it
  for a missing file. If it does not, a machine with no `shell.json` would
  keep payloads queued. The smoke harness's `fresh` scenario has no
  `shell.json`, so it covers this.
- **Payload sources:** any local process can call `omarchy-shell` already.
  The payload only sets search text, capped and cleaned, and never reaches
  a shell or a request.
- **Hosts:** a panel, menu and docs change, released through the usual
  chain to p620 and razer. p510 stays on 1.0.0.

## Verification

- `node tests/model.cjs`, `openFilter`:
  - `"{}"`, `""`, `"null"`, `"[]"`, `"3"`, `"{bad"`, `{filter: 3}` and
    `{filter: "  "}` all give `{null, ""}`;
  - `'{"filter":" group/p "}'` gives `group/p`;
  - a filter with `\n` and `\u0007` has them removed;
  - lengths: 200 characters passes, 201 is rejected;
  - an object payload, not a string, works;
  - host:
    - a filter with `\u0085` (a C1 control) has it removed;
  - a matching host passes, case-insensitively;
    - the panel host `gitlab.example.org:8443` matches the remote host
      `gitlab.example.org`;
    - a mismatch gives the notice and a `null` filter;
    - `host: 5` and `host: ""` give `{null, ""}`.
- `python3 -m unittest discover -s tests`, in `tests/test_menu.py`:
  - **`remote()`:**
    - the three forms from the intent;
    - `git@host:g/p` without `.git`;
    - `https://u@Host/g/s/p/`;
    - nested groups;
    - rejected: a local path, `file:///x/y`, `https://host/`,
      `https://host/p` (one segment), `git@host:/abs/path`,
      `https://host/g/../p`, `https://host/g%72oup/p`,
      `https://[broken/g/p`, `git@[::1]:g/p.git`, `https://host/g/p q` and
      an unknown scheme.
  - **`main()` with `open`**, with `quickshell list`, `git` and
    `os.execvp` patched:
    - `open 'a"b\\c\n$(x)'` passes exactly
      `json.dumps({"filter": 'a"b\\c\n$(x)'})` as the fifth argument;
    - `open` in a repository gives the filter and the host;
    - with no remote, an unsupported one, a missing `git` or a timeout, it
      sends `{}`, prints the stderr line, and still calls `execvp`;
    - `open a b` is a usage error.
- `tests/qml-smoke.py`, run in a `nixarchy-desktop` microVM only. New
  `esteps` with `workerBusy=true`:
  - `panel.open('{"filter":"one"}')`: `filterText` is `one`, the cursor is
    0, and after a tick the list item itself has `activeFocus`;
  - with help open and the cursor moved, the same payload again gives
    help closed and the cursor back at 0;
  - `panel.open("{}")`, a bad JSON payload and an oversized filter each
    leave `filterText` and the cursor unchanged;
  - two valid payloads, then an invalid one, leave the second filter: the
    last valid filter wins;
  - a host mismatch leaves the filter unchanged and sets the notice. A
    valid payload straight after it applies its filter and clears the
    notice;
  - with `configured` set to `false` (a test hook), a payload is queued,
    leaving `filterText` unchanged. `configure()` with a test config then
    applies it against the configured host. A payload for
    `gitlab.com` against a configured `gitlab.example.org` gives the
    notice, not the filter;
  - with focus in the search box, a filtered open moves focus to the list.
- **Manual check after deploy:** `menu.py open` in a GitLab checkout opens
  the panel on that project, and in a GitHub checkout shows the host
  notice.

## Review notes

Codex reviewed the draft read-only. It confirmed the line references, the
order in `open()`, the same-filter branch, and that `json.dumps` with one
`execvp` argument keeps the shell out. Its findings, which I checked in
the code and folded in above:
- a payload arriving before `shell.json` loaded was compared with the
  default `gitlab.com`, and `configure()` keeps `filterText`
  (`PipelinesPanel.qml:213-223`). Payloads now wait for the first
  configuration;
- `urlsplit` raises `ValueError` on `https://[broken/g/p`, and a missing
  `git` or a timeout raises too. Each would have reached the outer handler
  and returned 1 without opening. They are now caught;
- percent-encoded paths could not match. They are now rejected;
- a host warning could linger over a valid filter. It is now cleared;
- C1 controls, bracketed SCP hosts, internal whitespace and SCP ports are
  now defined. Tests now cover "last valid wins", cursor preservation and
  real list focus.
