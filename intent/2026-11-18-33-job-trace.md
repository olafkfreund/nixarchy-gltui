# Intent: Open a job's log with t

## Problem

The panel shows a job's status, duration and failure reason (#28), but
not its log. To read why a job failed, the user presses `o` to open the
job page in a browser, or switches to a terminal and works out the
command by hand. That command needs:
- the job id, which the panel never shows;
- the project path;
- the host. For a self-managed instance, `glab` uses that host only if
  you pass it a full URL. I checked this: `glab ci trace 1 -R
  https://gitlab.example.invalid/g/p` asks `gitlab.example.invalid`, while
  `-R gitlab.example.invalid/g/p` does not.

So the step from "this job failed" to "here is its log" is the slowest
part of using the panel.

## Proposed outcome

- **`t` on a job row** opens a terminal running
  `glab ci trace <job-id> -R https://<host>/<project>` for that job:
  - on the host the panel uses;
  - live while the job runs, as `glab ci trace` streams the log;
  - the full log for a finished job.
- **The window stays open** after `glab` exits, until the user presses a
  key, so a finished job's log and any `glab` error can be read.
- **The panel closes** when the terminal opens, so the terminal is not
  hidden behind the full-screen panel.
- **On any other row,** `t` shows the footer notice `Select a job to
  open its log` and does nothing else.
- **The terminal** is the user's default, through Omarchy's own launcher
  (`omarchy-launch-tui`, which runs `xdg-terminal-exec`).
- **No string reaches a shell.** The job id must be a positive integer
  from GitLab's reply, the project must pass the existing `project_path`
  rule (`gitlab.py:31`), and the host the existing `host_name` rule.
  Each is passed as its own argument, never pasted into a command line.
- **Docs:** the README key table, `keybindings.sh` (also shown by `?`)
  and the footer hint gain `t`.

## Affected users and systems

- **Files:**
  - `PipelinesModel.js`: job rows gain the job id;
  - `PipelinesPanel.qml`: the `t` key;
  - a small launcher (see question 3);
  - `README.md`, `keybindings.sh`;
  - tests: `tests/model.cjs`, a Python test for the launcher, and
    `tests/qml-smoke.py`.
- **Requirements:** a terminal that `xdg-terminal-exec` can start. Omarchy
  sets one up.
- **Hosts:** p620 and razer through the usual chain. p510 stays on its
  current version.

## Constraints

- Read-only, as the plugin is: `glab ci trace` only reads the log. No
  retry or cancel.
- No new GitLab request from the panel: the job id comes from data it
  already has.
- Authentication is `glab`'s own, as for the panel (README,
  Authentication).
- Smoke tests run in the microVM only, never on the host desktop. Tests
  must not open a real terminal or run a real `glab`; they swap the
  launcher command, as the copy tests swap `wl-copy` (#29).

## Open questions

1. **Key:** I recommend `t` ("trace"), as the issue says. It is free.
2. **Close the panel?** I recommend closing it on launch. The panel is a
   full-screen overlay with exclusive keyboard focus, so a terminal opened
   behind it cannot be used until it closes anyway.
3. **How to launch:** I recommend a new `trace` verb in `menu.py`, which
   already ships, already runs commands with `execvp` and has Python
   tests. It validates the three values with the rules from `gitlab.py`
   and execs `omarchy-launch-tui --app-id=org.omarchy.gitlab-trace`,
   which runs a short fixed script (`glab ci trace "$1" -R "$2"`, then
   "press any key"). The values reach it as positional arguments
   (`sh -c '<fixed script>' sh <id> <url>`), so they are never parsed by
   the shell. The alternative, building the terminal command in QML,
   would put the rules in a second language with no unit tests.
4. **Rows inside a job's stage or run:** I recommend job rows only. On a
   pipeline, `glab ci trace` without a job asks interactively, which does
   not fit a one-key action. `e` (#29) already jumps to the next failed
   job.
5. **Host with a port** (`gitlab.example.org:8443`): the URL keeps the
   port. I have not checked that `glab` honours it in `-R`; the spec
   will check it and say what happens if not.
