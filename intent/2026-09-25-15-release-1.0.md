# Intent: Port nixarchy-ghtui's pre-1.0 fixes, then release 1.0.0

## Problem

gltui is a port of nixarchy-ghtui, which tagged v1.0.0 on 2026-09-24 after a
round of fixes. gltui is still `0.1.0` with no tag, and it has the same design
gaps that ghtui fixed before its release:

- **A broken helper freezes the panel or leaks its output.** If `python3` is
  missing, the helper process never starts, `workerBusy` never clears, and
  polling stops with no message. When the helper does fail, its raw stderr is
  shown in the panel (`PipelinesModel.js:3`) instead of a clear cause.
  (ghtui #24)
- **A large project can stall the panel.** Every unfinished pipeline is kept
  with no limit (`Polling.js:141`), and `syncRows` in `PipelinesModel.js`
  searches the model for each row and compares each row with
  `JSON.stringify`. A project with thousands of pending pipelines gets slow
  in proportion to the square of that number. (ghtui #30)
- **Untrusted text is shown as is.** Branch names, pipeline and job names come
  from GitLab and can contain control or format characters, such as bidi
  overrides that visually reorder text. `gitlab.py` does not strip them. The
  package also doesn't declare what it needs at runtime. (ghtui #32)

## Proposed outcome

- A helper that can't start, crashes or replies with garbage produces a
  specific message in the panel, and polling recovers when you refresh. No
  raw stderr in the panel.
- A project with thousands of pending pipelines stays responsive.
- Text from GitLab is shown without control or format characters (joiners
  that emoji need are kept, as ghtui does).
- The package declares its runtime dependencies (`glab`, `python3`,
  `xdg-utils`), as ghtui's does.
- gltui is released as **1.0.0**: manifest bumped, tag `v1.0.0`, GitHub
  release notes, nixarchy pin bumped.

## Affected users and systems

- Code: `PipelinesPanel.qml`, `PipelinesModel.js`, `Polling.js`, `gitlab.py`,
  `flake.nix`, `manifest.json`, tests.
- nixarchy: one pin bump PR after the release.
- Users: no change on the normal path. The panel still looks and sizes the
  same as ghtui (#12).

## Constraints

- Follow ghtui's fixes where the code is the same shape; don't invent new
  behaviour. Where GitLab differs (for example pagination), adapt the approach
  and say why.
- No new dependencies, no config changes, and the plugin id stays the same.
- Keep #12's sizing untouched.
- Must pass `nix flake check`, the QML smoke test and `omarchy plugin validate`.

## Open questions

1. **Scope.** One task for all three fixes plus the release, or three smaller
   tasks? Default if unanswered: **one task**, one PR per fix (three PRs),
   then a release PR. That matches ghtui's history and keeps reviews small.
2. **Limit for unfinished pipelines.** ghtui fetches one page of 100 per
   unfinished status and shows a "+N more queued" row that `o` opens on
   GitHub. Default if unanswered: **the same for gltui**, with `o` opening the
   project's pipelines page on GitLab.
