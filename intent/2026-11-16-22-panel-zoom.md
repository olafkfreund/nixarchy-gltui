# Intent: Zoom the panel text with keys

## Problem

The panel's fonts and most of its layout come from the shell's type and
spacing scale (`Style.font.*`, `Style.space()` and `Style.spacing.*`). The
card size, row heights and indents all pass through `Style.space()`, and other
sizes follow the fonts (`PipelinesPanel.qml:242-401`). Those sizes come from `[font] base-size` in
`~/.config/omarchy/shell.toml`.

On the owner's 2560×1440 monitors at scale 1, the default base size of 12 gives
12 px body text and 10 px secondary lines (`Style.font.caption`). The owner
finds that too small to read.

The only fix today is to raise `base-size`, which resizes the whole shell: bar,
menus and every other panel. The owner did that (12 → 15) as a stopgap, and
asked to be able to make the panel bigger and smaller with keys when needed.

## Proposed outcome

- **Ctrl + =** (also **Ctrl + +**) makes the panel larger, and **Ctrl + -**
  makes it smaller. **Ctrl + 0** returns to the shell's own size.
- The zoom multiplies the shell sizes the panel already uses, so it stacks on
  top of `base-size` rather than replacing it.
  - Text, row heights, indents and padding grow together, and rows never
    overlap.
  - The border width, the separator hairline, the corner radius and the outer
    gap to the screen edge stay at the theme's values. They frame the panel and
    don't carry text.
- The card grows with the zoom up to the existing cap: the window size minus
  twice `Style.gapsOut` (`PipelinesPanel.qml:242`).
  - Past the cap, zooming in shows fewer rows, and long titles elide as they do
    today.
  - The selected row stays in view after every zoom step.
- The zoom is limited to a fixed range (open question 1).
- The current zoom percentage shows whenever it is not 100%, in its own place
  that is never elided and never replaced. Today the footer hints elide, and a
  cooldown message replaces them (`:395`), so appending the percentage there
  would not keep it visible.
- The zoom survives closing and reopening the panel while the shell runs. It
  resets when the shell restarts.
- The keys work both in the list and in the search field.
  - In the search field they change neither the query, nor the text selection,
    nor which field has focus. Today the field's handler passes every
    unhandled key to native text editing (`:298-310`), so the zoom keys must
    be caught before that.
  - They match `Qt.Key_Equal`, `Key_Plus`, `Key_Minus` and `Key_0` with Ctrl,
    with or without Shift, because some layouts need Shift to type `+`.
  - Ctrl combined with Alt, AltGr or Super is not a zoom key.
  - The check presses real keys in both focus states. Calling the zoom
    function directly does not count.
- The README key table and the Omarchy keybindings menu list the new keys.

## Affected users and systems

- Anyone using the plugin. It is user-level only: no NixOS host changes and no
  p510 builds.
- Files: `PipelinesPanel.qml`, `README.md`, `keybindings.sh` (the key reference
  menu), and the tests (`tests/qml-smoke.py`, or a model test if the sizing
  maths moves into `PipelinesModel.js`).
- The GitHub sibling `nixarchy-ghtui` has the same panel and could take the
  same change later. That is out of scope here.

## Constraints

- No buttons, and no mouse-only control: the panel stays keyboard-driven.
- No new files or storage for the zoom. It lives in memory
  (`manifest.json:6` sets `keepLoaded: true`, and closing the panel does not
  recreate it). The existing menu registration is unaffected.
- Keep using the theme's font family, colours and tokens. The zoom is a factor
  on them, not a separate set of sizes.
- No new runtime dependencies.
- Must not conflict with the existing keys (`j`/`k`, `r`, Shift+R, `o`, `/`,
  Escape and the rest), or with Hyprland bindings that use Super.
- Lands after #21. It may touch the same `PipelinesPanel.qml` lines as #21's
  step 12, so it is rebased onto #21's merge before implementation.

## Open questions

1. **Range and step:** the proposal is 75%–200% in steps of 10 percentage
   points from 100%: 80, 90, 100, 110 … 200. 75% is reached only as the lower
   clamp, and stepping up from it goes to 80%. The steps are added, not
   multiplied by 1.1. The alternative is the shell's own steps: one
   `base-size` point is about 8% at 12 but about 7% at 15, so the steps would
   be uneven.
2. **Keeping the zoom across shell restarts:** the proposal is no. Keeping it
   would need storage, which this plugin keeps for nothing else.
3. **Should the card grow with the zoom?** The proposal is yes, up to the
   existing cap. Either way, once the card reaches its limit, zooming in shows
   fewer rows.
