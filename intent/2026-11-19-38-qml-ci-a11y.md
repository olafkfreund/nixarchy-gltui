# Intent: Run the QML smoke test in CI and add accessibility roles

## Problem

**The QML is never loaded in CI.** `.github/workflows/check.yml` runs
`nix flake check`. Its `plugin` check (`flake.nix:51-89`) runs the Python,
model and scheduler tests, but calls `tests/qml-smoke.py` only with a
missing directory, to check the argument error. The real smoke test
(1,825 lines, two scenarios) runs only by hand, now in a microVM. A QML
error, a binding loop or a broken key path can reach `main` and a release
without CI noticing.

The smoke test needs more than a build sandbox gives it:

- `quickshell` and a Wayland compositor with layer shell. The panel is a
  `PanelWindow` (`PipelinesPanel.qml:584-593`) and imports
  `Quickshell.Hyprland` (`:5`, `:119`).
- The Omarchy shell's `Commons` and `Ui` from `$OMARCHY_PATH/shell`
  (`tests/qml-smoke.py:16`), and a theme `colors.toml` under `$HOME`
  (`:17`). Nixarchy provides both; this repo has no input for them.
- `wl-copy` and `wl-paste` for the K3-K5 copy checks, and the shell
  tools other checks run (`tests/qml-smoke.py:1046`, `:1083`, `:1565`).
- Qt's `QtTest` module (`:66`), fonts, and the caller's fontconfig and
  `~/.config/omarchy/shell.toml`, which the harness links in (`:56-58`).
- Python and Bash for the helper and menu processes
  (`PipelinesPanel.qml:499`, `:556`), and the session's environment
  (`tests/qml-smoke.py:1812`).
- Software rendering in a VM (nixarchy's `tests/session.nix:190`).
- Keyboard focus: an idle or locked session makes every `keyClick` fail.

**Most key checks already use real key events.** Since #22 the harness
sends QtTest `keyClick`, through `pressKey` (`tests/qml-smoke.py:91-96`,
48 calls) and directly (9 calls). A few checks still call panel functions
where a key exists: `panel.toggleHelp()` (`:1185`, `:1333`, `:1408`), and
`panel.move(1)` (`:1630`, `:1667`) with `panel.expand(...)` (`:1632`,
`:1634`, `:1666`, `:1668`). The `move`/`expand` checks run before the
panel opens (`panel.open` at `:1670`), so they need an opened, focused
stage, not a key in place. `panel.refresh(...)` (`:1725`, `:1773`) is a
timing test of an overlapping request, not a key test.

**No accessible roles or names are set.** `PipelinesPanel.qml` sets no
`Accessible.*` property. Qt's defaults give a row no role that says it is
a list item and no name that includes its status, which is shown only as
a colour. The search box (`TextInput`, `:665`) and the footer (`:814`) get
no name either.

## Proposed outcome

- A pull request or push to `main` runs the full QML smoke test, both
  scenarios, headless, with no GitLab access and no user desktop. A
  failing smoke check fails the run.
- The checks above that stand for a key press send the key instead.
- Each row, the search box and the footer has an `Accessible.role` and an
  `Accessible.name`. A row's name says what the row is and its status
  (for example "a/one, pipeline 12, failed"), not only its colour.
- The smoke test checks those properties for each row kind (repository,
  pipeline, stage, job, trigger, message). It does not prove what a
  screen reader announces; a manual check with the ai-mirror
  accessibility tools in the microVM covers that once.

## Affected users and systems

- This repo: `.github/workflows/check.yml`, `flake.nix` (if the test
  becomes a flake check), `tests/qml-smoke.py`, `PipelinesPanel.qml`,
  `README.md`.
- CI time on GitHub runners. Nothing changes on p620, razer or p510 until
  the next deploy, which ships only the QML accessibility change.
- Screen reader users and the ai-mirror accessibility tools.

## Constraints

- Never run the smoke test, quickshell or `notify-send` on the host
  desktop. Local runs stay in a microVM.
- CI must not contact GitLab or need a token. The smoke test already uses
  a fake helper.
- Nixarchy already pins this repo (`nixarchy/flake.nix:293-294`). If the
  test needs nixarchy, that input must not reach the runtime package, and
  must not grow nixarchy's own lock with a nested copy of itself.
- Accessibility names must not change what is drawn or the key bindings.
- The runtime package stays the same files (`flake.nix:15-24`).
- Quickshell 0.3.1 behaviour, as used today.

## Open questions

1. **How CI gets a compositor and the Omarchy shell.**
   - (a) A NixOS VM test (`runNixOSTest`) that boots the nixarchy desktop,
     like nixarchy's `tests/session.nix`. It needs `/dev/kvm`, which
     nixarchy's CI already enables on `ubuntu-latest`
     (`build.yml:1704-1714`).
   - (b) A headless compositor in the runner, with no VM.
   - Recommendation: (a), a focused VM rather than a copy of the broad
     session test (6 GiB, four cores, `session.nix:219-221`). It runs the
     real Hyprland and shell the users have. It gets the Omarchy tree
     from nixarchy's exported modules, through a CI-only input or
     checkout, and tests this PR's files, not nixarchy's pin. The spec
     proves the wiring and the run time.
2. **Where the VM test lives.** Anything under `checks` runs on every
   `nix flake check`, locally too, and would start a VM. Recommendation:
   a package outside `checks` (for example `packages.<system>.qml-smoke`),
   built by its own CI job with KVM, as nixarchy's `box` job does
   (`build.yml:1704-1719`). The spec picks the path.
3. **How much a row's name says.** Recommendation: the title, the kind
   and the status, with a defined text when the status is unknown. Times
   change every second, so they stay out of the name.
