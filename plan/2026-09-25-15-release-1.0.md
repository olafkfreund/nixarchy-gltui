# Plan: Port nixarchy-ghtui's pre-1.0 fixes, then release 1.0.0

Approved decisions (from the spec):

- One task, **four PRs merged in order**: A (helper failures, carries the
  intent/spec/plan), B (large projects), C (untrusted text and runtime deps),
  then the release. Each PR is based on main after the previous one merges,
  and merges once its CI is green. Approving this plan approves those merges,
  the `v1.0.0` tag and release, and the nixarchy pin-bump PR.
- Each fix copies the shipped ghtui change (PR #28, #35, #37) and adapts only
  what GitLab needs:
  - totals come from the `X-Total` header; a missing header with `X-Next-Page`
    set gives `-1`;
  - the unfinished statuses are `running`, `pending`, `created`,
    `waiting_for_resource` and `preparing`;
  - the "more" row's url is `<project url>/-/pipelines`;
  - the host is a parameter of `browsable`.
- A helper that returns bad data now stops polling until manual refresh
  (`errorType: "setup"`). This revises #10's retry-as-`network`.
- `shownFields` = `title`, `subtitle`, `status`, `info`. The delegate also
  reads `key`, `kind` and `depth`, which never change for a given key.
- Every new test must fail on the pre-fix code, the same as #10. Sizing from
  #12 is left untouched.

## Steps

### PR A: `fix: a failing helper shows its real cause (#15)`, branch `feat/15-release-1.0`

1. `PipelinesModel.js` `reply(stdout, code, requestId)`:
   - Drop the `stderr` parameter.
   - With empty stdout, return
     `{requestId, errorType:"setup", error: code===127 ? "python3 not found" : "GitLab helper failed (exit "+code+"); see the shell log"}`.
   - Add the comment "Fixed text only: stderr can hold paths and tracebacks,
     so it goes to the log, never the panel."
2. `PipelinesPanel.qml`, copied from ghtui PR #28 with "GitLab Pipelines"
   in the log messages:
   - `property bool helperStarted: false`, reset in `pump()` before `running = true`.
   - `function failedToStart()`: it warns, calls
     `receivePage(Model.reply("", 127, requestInfo.requestId), requestInfo)`,
     then sets `workerBusy = false`.
   - In `receivePage`'s catch: `console.warn` the first 300 characters, and
     reply with `errorType:"setup"` and "GitLab helper returned invalid data;
     see the shell log".
   - `requestProc`:
     - `onExited` warns with non-empty stderr and calls
       `Model.reply(pageOutput.text, code, root.requestInfo.requestId)`;
     - `onStarted: root.helperStarted = true`;
     - `onRunningChanged: if (!running && root.workerBusy && !root.helperStarted) root.failedToStart()`,
       with the Quickshell 0.3.1 comment.
3. `Polling.js` `complete`:
   - The list shape check also requires
     `reply.data.every(function(x) { return x && typeof x==="object" })`.
   - The replacement reply uses `errorType:"setup"`.
   - `if (reply.errorType==="auth" || reply.errorType==="setup") s.auth=true;`
     with ghtui's `ponytail:` comment.
4. `gitlab.py`:
   - In `read_page`, before the generic `except`:
     `except FileNotFoundError: result.update(data=None, errorType="setup", error="Install glab (GitLab CLI)")`,
     with ghtui's `ponytail:` comment.
   - In `main()`: set `task = None` before the `try`, and assign
     `task = json.loads(...)` before `read_page`. The error JSON gets
     `errorType` (`"network"` for `DeadlineExceeded`, `TimeoutExpired` or
     `OSError`, otherwise `"setup"`) and `requestId` when the task's is a
     positive int.
5. Tests:
   - `tests/model.cjs`: `reply('',127,5)` → "python3 not found", `setup`,
     `requestId` 5; `reply('',2,5)` names exit 2 and contains no stderr.
   - `tests/polling.cjs`: `data:[1]` for a list task → `setup` error,
     `s.auth` true, `next()` null until `manual()`. Update #10's bad-shape
     test from `network` to `setup`.
   - `tests/test_gitlab.py`:
     - `request` raising `FileNotFoundError` → `setup` / "Install glab";
     - `main()` with an invalid task → `errorType` `setup` and no `requestId`;
     - `main()` with a `DeadlineExceeded` task carrying `requestId` 7 →
       `network` and `requestId` 7.
   - `tests/qml-smoke.py`: a new check sets `panel.helper` to a missing path,
     calls `pump()`, and waits until `workerBusy` is false and
     `polling.error` is "python3 not found" or a setup error. If this has no
     `failedToStart` trigger in the test host, record the deviation here.

   → verify: `nix flake check`, the smoke test prints `QML_CHECKS_PASSED`
   (source and `./result`), and the new tests fail on `main`.
6. Push `feat/15-release-1.0`, open PR A with the artifacts and "Part of
   #15", and merge it once CI is green.

### PR B: `fix: keep the panel responsive for large projects (#15)`, branch `fix/15-large-projects`

7. `gitlab.py` `read_page`, list branch:
   - For `kind=="activity"` or `task.get("status") in PHASES`: parse
     `headers.get("x-total")`. Missing and `x-next-page` non-empty → `-1`.
     Missing otherwise → `len(body)`. Present → must be `^[0-9]+$`, else
     `ValueError("Invalid pipeline total")`. Store it as `result["total"]`.
   - `nextPage` is set only for `catalogue` and `jobs`.
8. `Polling.js`, from ghtui PR #35:
   - `kept(s,r,run)`; `recent`/`trimRuns` keep `kept` runs;
   - `activity(s,r,items,now,total)` with the partial-page `dropped` logic,
     `r.active` from `total`, and
     `r.hidden=Object.assign({},r.hidden,{running:total<0?-1:Math.max(0,total-items.length)})`;
   - in the summary branch: `(t.hidden=t.hidden||{})[phases[t.phase]]` from
     `reply.total` for unfinished phases, then `r.hidden=t.hidden||{}` at the
     end;
   - `activity(..., reply.total)` at both call sites. `running` replaces
     `in_progress` throughout.
9. `PipelinesModel.js`:
   - In `rows()`, build the "more" row for statuses
     `["running","pending","created","waiting_for_resource","preparing"]`.
     Each part is `+N more <status>`, `+about N more` above 1000, or
     `+more <status>` for `-1`. The subtitle is "o opens GitLab", and the url
     is `repo.url + "/-/pipelines"`. Insert it before the first completed
     pipeline, or at the end.
   - Replace `syncRows` with ghtui's linear version and `shownFields`.
10. Tests:
    - `tests/test_gitlab.py`: a running summary with `X-Total: 250` and
      `X-Next-Page: 2` → `total` 250 and `nextPage` 0; no `X-Total` with
      `X-Next-Page` → `-1`; `X-Total: x` → `network`; `jobs` still
      paginates.
    - `tests/polling.cjs`: `total` 250 with 100 items → `r.hidden.running`
      150; a partial page drops a run nobody is viewing and keeps an expanded
      one. The idle and budget test must still beat its baseline.
    - `tests/model.cjs`: the "more" row's text, position and url, plus "about
      N" and `+more`. `syncRows` on a fake model with 3,000 rows, reversed:
      the result order is correct and `get` calls stay under 20·n.

    → verify as in step 5. Push, open PR B, merge once green.

### PR C: `fix: harden untrusted GitLab text and URLs, declare runtime deps (#15)`, branch `fix/15-untrusted-text`

11. `gitlab.py`:
    - `import unicodedata`, `JOINERS = "‌‍"`, and `plain(value)`
      as in ghtui.
    - Apply it in `project()` to `description`, in `pipeline()` to `name` and
      `head_branch`, and in `job()` to `name` and `stage`.
12. `PipelinesModel.js`:
    - `browsable(url, host)`:
      `new RegExp("^https://" + host.replace(/[.*+?^${}()|[\]\\]/g, "\\$&") + "/[^\\s\\x00-\\x1f\\x7f-\\x9f]+$").test(url)`,
      guarded by `typeof url === "string"`.
    - `PipelinesPanel.qml` `openBrowser()` uses `Model.browsable(current.url, host)`.
13. `flake.nix`: `passthru.runtimeDeps = [ pkgs.glab pkgs.python3 pkgs.xdg-utils ];`
    in the `runCommand` attribute set, with ghtui's comment.
14. Tests:
    - `tests/test_gitlab.py`: `plain("a‮b\u0007c")` == `"abc"`; ZWJ kept;
      `"a\nb\tc"` → `"a b c"`; a pipeline `ref` with U+202E comes out clean.
    - `tests/model.cjs`: `browsable` true for
      `https://gitlab.com/g/p/-/pipelines/1`; false for another host,
      `https://gitlab.com.evil/x`, a URL containing `\u0007` or a space, and
      a non-string.
    - `nix eval --json .#packages.x86_64-linux.default.runtimeDeps` names
      glab, python3 and xdg-utils.

    → verify as in step 5. Push, open PR C, merge once green.

### Release

15. Branch `chore/release-1.0.0`: `manifest.json` `version` → `1.0.0`
    (only that line). PR titled `chore: release 1.0.0`, merged once green.
16. `git tag v1.0.0 <merge commit>`, push the tag, then
    `gh release create v1.0.0 --title v1.0.0 --notes-file` with notes in
    ghtui's shape:
    - Highlights: theme-sized text and fixed card (#6, #12); helper errors
      (A); large projects (B); hardened text, URLs and runtime deps (C);
      error handling (#10).
    - Maintenance: CI, the GitLab port renames (#7, #9).
    - Upgrade notes: text at theme size, fixed 900×680 card, and a
      "nixarchy users get it after the pin bump" line linking the PR.
17. nixarchy: branch `chore/bump-nixarchy-gltui-1.0.0`, pin →
    `v1.0.0`'s commit, `nix flake lock --update-input nixarchy-gltui`.
    Build `options`, `menu-verbs` and `plugin` locally. Open the PR and turn
    on auto-merge (squash).

## Tests

- Per PR: `nix flake check` → all checks passed; `python3 tests/qml-smoke.py`
  and `./result` → `QML_CHECKS_PASSED`; `omarchy plugin validate` → exit 0;
  the new tests fail on the base commit; GitHub Actions `check` is green.
- Release: `jq -r .version manifest.json` → `1.0.0`; `gh release view v1.0.0`
  shows the notes; nixarchy's `options`, `menu-verbs` and `plugin` pass.

## Rollback

- A fix PR: `git revert` its merge commit, which is independent per fix.
- The release: `gh release delete v1.0.0 --cleanup-tag`, then revert the
  manifest bump; close the nixarchy PR, or revert it if merged.
