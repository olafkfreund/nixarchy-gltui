# Plan: Show the latest pipeline status on each project row

## Decisions (from the approved spec)

- No new requests; `Polling.js`, `gitlab.py`, `PipelinesPanel.qml` unchanged.
- `latest(runs)`: highest numeric `id` among runs with
  `status === "completed"`, no `awaitingFinal`, no `lookupError`; `null` if
  none. Always called on `repo.runs || []`, never on the search-filtered
  local `runs`.
- Repo row `status`: `repo.error` → `"error"`; `active > 0` → `"running"`;
  latest → `state(latest)`; else `"neutral"`.
- Repo row `info`: as today, plus `"no pipelines"` when
  `repo.summaryAt !== undefined` and `(repo.runs || []).length === 0`, after
  the archived/disabled/error cases and before the `N running` /
  `not checked` cases.
- Repo row gains `lastStatus` (`state(latest)`) and `lastAt`
  (`latest.completed_at || latest.updated_at || ""`), both `""` when there is
  no latest or `repo.error` is set. Add both to `shownFields`.
- `infoText()` repo branch: `info` + (`lastStatus` ? ` · last ` + lastStatus
  + (age ? " " + age : "")) + the existing ` · checked <ago>` suffix only
  when `info` ends in `running`. Example:
  `0 running · last failed 2h ago · checked 3m ago`.
- Sort order unchanged. Version 1.11.0.
