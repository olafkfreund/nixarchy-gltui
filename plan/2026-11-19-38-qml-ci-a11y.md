- **`accessibleName(row)` in `PipelinesModel.js`:**
  - the parts are the title, a kind word, then the marks, then a status
    word, joined with `", "`;
  - kind words: repo "project", run "pipeline", stage "stage", job
    "job", trigger "downstream pipeline". `more` and `message` rows give
    only the title;
  - marks: "pinned" when `kind === "repo" && pinned`, and "watched" when
    `kind === "run" && watched`;
  - status words come from `group(status)`. `success` → "passed",
    `allowed` → "failed, allowed", and running, failed, manual, scheduled,
    queued, skipped, canceled stay as they are. `neutral` and `unknown`
    give "no status";
  - no times;
  - example: `"a/one, project, pinned, failed"`.
- **Status-change check.** It changes a run's status in the polling state
  and calls `adopt()`, which is the path a merged reply takes. It does not
  rewrite the fake helper's reply file mid-run, because of the `FileView`
  trap. This is how the spec's "a fake reply moves a pipeline from
  running to failed" is carried out.
