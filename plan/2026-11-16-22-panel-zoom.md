# Plan: Zoom the panel text with keys

Self-contained. Branch `feat/22-panel-zoom` (worktree `../nixarchy-gltui-22`),
based on `1a7587b` (v1.0.1). Line numbers are for that commit. Match on the
quoted code.

## Approved decisions (from the spec)

- `zoomPercent` (an int, default 100) lives on the panel root. It is kept in
  memory while the shell runs (`keepLoaded: true`), with no persistence.
- Steps go 75–200 in 10-point steps from 100. `zoomStep(p, +1)` is
  `min(200, floor(p/10)*10+10)`, `zoomStep(p, -1)` is
  `max(75, ceil(p/10)*10-10)`, and `zoomStep(p, 0)` is `100`.
- `zf(v) = Math.round(v*zoomPercent/100)` for font pixel sizes, and
  `zs(v) = v*zoomPercent/100` for layout sizes.
- These stay at the theme value: `Style.gapsOut`, `Style.cornerRadius`, the
  border width `Math.max(1, Style.space(2))`, and `Style.spacing.hairline`.
- The card is `Math.min(zs(Style.space(900)), window.width - Style.gapsOut*2)`,
  and the same for the height with 680.
- Keys:
  - `Ctrl` + `Key_Equal`/`Key_Plus` zooms in, `Key_Minus` zooms out, and
    `Key_0` resets.
  - Shift and the keypad are allowed. Alt or Meta (which includes AltGr and
    Super) means no zoom.
  - Both `Keys.onPressed` handlers check `root.zoomKey(event)` first. When it
    returns true they set `event.accepted = true` and return.
- `onZoomPercentChanged` keeps the cursor row in view with `Qt.callLater`,
  `forceLayout()` and `positionViewAtIndex(cursor, ListView.Contain)`.
- The footer becomes an `Item` with `id: footer`. Its height is
  `Math.max(hint.implicitHeight, zoomLabel.visible ? zoomLabel.implicitHeight : 0)`.
  It holds:
  - the old text as `hint`, with width
    `parent.width - (zoomLabel.visible ? zoomLabel.implicitWidth + zs(Style.spacing.sm) : 0)`
    and `ElideRight`;
  - `zoomLabel`, anchored right, showing `zoomPercent + "%"`, visible when
    `zoomPercent !== 100`, never elided;
  - the cooldown text still replaces only `hint`.
- Test hooks: `readonly property Item cardItem: card`, `listItem: list`,
  `searchItem: searchField`, `hintItem: hint`, `zoomItem: zoomLabel`.
- Release as 1.1.0.

## Probe result (spec risk 1, done before this plan)

QtTest's `TestCase.keyClick` delivers real key events inside a plain
`quickshell` process. Two conditions:

- **Use `TestCase { when: false }`.** A `TestCase` with `when: true` runs its
  own tests and quits the process.
- **Assert the zoom value.** In the probe, `Ctrl+=` reached a list handler and
  `Ctrl+-` reached a `TextInput` handler. The `TextInput` kept its text `ab`,
  its selection `ab` and its focus. The handler counted 2 plain keys for one
  `j`, because the Ctrl press itself is a key event. So count zoom changes,
  not key presses.

No `wtype` is needed.

## Repo traps (all steps)

- `PipelinesModel.js` is plain ES5: QML imports it, and `tests/model.cjs`
  loads it with `vm`. Use `var` and `function`, with no `const`, `let`, arrow
  functions or `?.`.
- The smoke test opens a real window on the owner's desktop and must not send
  keys anywhere else. Use only `TestCase.keyClick`.
- The smoke log scan fails on any `TypeError`, `ReferenceError`, `ERROR:` or
  `CHECK FAILED` (`tests/qml-smoke.py`, near the end).
- Keep `Commons.Color`: a bare `Color` breaks on Qt 6.12 (#20).
- Never stage, commit or push from the coder. The lead commits after each step.

## Steps

1. **`PipelinesModel.js`**: add `function zoomStep(percent, direction)` as
   above. In **`tests/model.cjs`**, for every integer 75..200 and both
   directions, assert:
   - the result is a multiple of 10 or exactly 75, lies in [75, 200], and
     moves strictly in the requested direction (unless already at the limit);
   - there is no allowed level between the input and the result;
   - `zoomStep(p, 0) === 100`;
   - the explicit sequence `100 → 90 → 80 → 75 → 75` going down and
     `75 → 80 → … → 200 → 200` going up.
   → verify by `node tests/model.cjs`
   Traps: none beyond ES5.

2. **`PipelinesPanel.qml`**:
   - add the root properties and functions from the decisions:
     `zoomPercent`, `zf`, `zs`, `zoomKey`, `onZoomPercentChanged`, and the
     test hooks;
   - wrap every `Style.font.*` pixel size in `root.zf(...)`;
   - wrap every `Style.space(n)` and `Style.spacing.md/sm/panelPadding` that
     sizes text, rows, indents or padding in `root.zs(...)`. These are at
     `:250-251` (inner term only), `:255`, `:288`, `:336` if it adds spacing,
     `:345`, `:350-352` and `:355`;
   - leave `:250-251` `Style.gapsOut`, `:253`, `:254` and `:332` untouched;
   - insert the `zoomKey` check at the top of both `Keys.onPressed` handlers
     (`:265` and `:306`), before their existing first line;
   - replace the footer `Text` (`:403-412`) with the footer `Item` described
     in the decisions.
   → verify by `python3 tests/qml-smoke.py`, which must still pass unchanged,
   then `nix flake check`.
   Traps:
   - `event.accepted = true` at the top of the list handler (`:266`) must not
     run before the zoom check;
   - the search placeholder `Text` (`:322-330`) inherits `searchField.font`,
     so it scales with no extra edit;
   - `rebuild()` uses `list.indexAt` geometry, so don't call it from the zoom
     handler.

3. **`tests/qml-smoke.py`**:
   - add `import QtTest` and `TestCase { id: tc; when: false }` to the
     generated `shell.qml`;
   - add new stages after the existing ones, with the panel open, keys focus
     on the list, and `Polling` quiet (`panel.polling.discover=false`, no due
     tasks; set `wakeAt = 0` after fixture writes);
   - **delivery:** `tc.keyClick(Qt.Key_J)` moves `panel.cursor` by 1;
   - **list keys:** `Ctrl+=` → 110, `Ctrl+Shift+=` (sent as `Key_Plus` with
     Ctrl and Shift) → 120, `Ctrl+-` → 110, `Ctrl+0` → 100;
   - **modifiers:** `Ctrl+Alt+=` and `Ctrl+Meta+=` leave the zoom unchanged.
     Assert delivery again right after with a `j`;
   - **search:** focus `panel.searchItem`, set its text to `ab`, `selectAll()`,
     then `Ctrl+-` → 90. The text is still `ab`, `selectedText` is `ab`, and
     `searchItem.activeFocus` is still true;
   - **scaling:** record at 100, then set 150 via keys (5×`Ctrl+=`) and wait
     one layout tick (`Qt.callLater` stage). The search font pixel size and
     the card padding grow ×1.5 (±1 px). `Style.spacing.hairline`,
     `Style.cornerRadius` and the border width are not referenced through
     `zs` (check on `cardItem`: `radius` unchanged);
   - **growth and cap:** `cardItem.width` and `height` at 120 are greater than
     at 100. At 200 each is `<=` the window size minus `2*Style.gapsOut`;
   - **selection in view:** a fixture of 40 configured projects, the cursor
     on the last row, then zoom to 200 and wait a tick. The last row's `y`
     lies within `listItem.contentY .. contentY+height`;
   - **indicator:** at 120, set `panel.polling.cooldown` far in the future so
     `cooldownText` shows. Force elision by reading `hintItem.truncated`
     after the card is narrowed, or by testing at 200. Then: `zoomItem.visible`,
     its text is `120%`, it lies inside the footer, and
     `hintItem.x + hintItem.width <= zoomItem.x`;
   - **survives close/open:** at 130, `close()` then `open()`, and the zoom is
     still 130.
   → verify by `python3 tests/qml-smoke.py` three times in a row, all passing.
   Traps: the zoom is per panel instance and the `fresh` and `managed`
   scenarios each start a new process, so assert from 100 in each.
