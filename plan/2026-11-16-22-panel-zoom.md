# Plan: Zoom the panel text with keys

Self-contained. Branch `feat/22-panel-zoom` (worktree `../nixarchy-gltui-22`),
based on `1a7587b` (v1.0.1). Line numbers are for that commit. Match on the
quoted code.

## Approved decisions (from the spec)

- `zoomPercent` (an int, default 100) lives on the panel root. It is kept in
  memory while the shell runs (`keepLoaded: true`), with no persistence.
- Steps go 75–200 in 10-point steps from 100. `zoomStep(p, +1)` is
  `min(200, floor(p/10)*10+10)`, `zoomStep(p, -1)` is
  `max(75, ceil(p/10)*10-10)`, and `zoomStep(p, 0)` is `100`.
- `zf(v) = Math.round(v*zoomPercent/100)` for font pixel sizes, and
  `zs(v) = v*zoomPercent/100` for layout sizes.
- These stay at the theme value: `Style.gapsOut`, `Style.cornerRadius`, the
  border width `Math.max(1, Style.space(2))`, and `Style.spacing.hairline`.
- The card is `Math.min(zs(Style.space(900)), window.width - Style.gapsOut*2)`,
  and the same for the height with 680.
- Keys:
  - `Ctrl` + `Key_Equal`/`Key_Plus` zooms in, `Key_Minus` zooms out, and
    `Key_0` resets.
  - Shift and the keypad are allowed. Alt or Meta (which includes AltGr and
    Super) means no zoom.
  - Both `Keys.onPressed` handlers check `root.zoomKey(event)` first. When it
    returns true they set `event.accepted = true` and return.
- `onZoomPercentChanged` keeps the cursor row in view with `Qt.callLater`,
  `forceLayout()` and `positionViewAtIndex(cursor, ListView.Contain)`.
- The footer becomes an `Item` with `id: footer`. Its height is
  `Math.max(hint.implicitHeight, zoomLabel.visible ? zoomLabel.implicitHeight : 0)`.
  It holds:
  - the old text as `hint`, with width
    `parent.width - (zoomLabel.visible ? zoomLabel.implicitWidth + zs(Style.spacing.sm) : 0)`
    and `ElideRight`;
  - `zoomLabel`, anchored right, showing `zoomPercent + "%"`, visible when
    `zoomPercent !== 100`, never elided;
  - the cooldown text still replaces only `hint`.
- Test hooks: `readonly property Item cardItem: card`, `listItem: list`,
  `searchItem: searchField`, `hintItem: hint`, `zoomItem: zoomLabel` (and
  `hairlineItem`, `borderWidth` if step 3 needs them), under a one-line
  comment saying they exist for `tests/qml-smoke.py`.
- Release as 1.1.0.

## Probe result (spec risk 1, done before this plan)

QtTest's `TestCase.keyClick` delivers real key events inside a plain
`quickshell` process. Two conditions:

- **Use `TestCase { when: false }`.** A `TestCase` with `when: true` runs its
  own tests and quits the process.
- **Assert the zoom value.** In the probe, `Ctrl+=` reached a list handler and
  `Ctrl+-` reached a `TextInput` handler. The `TextInput` kept its text `ab`,
  its selection `ab` and its focus. The handler counted 2 plain keys for one
  `j`, because the Ctrl press itself is a key event. So count zoom changes,
  not key presses.

No `wtype` is needed.

## Repo traps (all steps)

- `PipelinesModel.js` is plain ES5: QML imports it, and `tests/model.cjs`
  loads it with `vm`. Use `var` and `function`, with no `const`, `let`, arrow
  functions or `?.`.
- The smoke test opens a real window on the owner's desktop and must not send
  keys anywhere else. Use only `TestCase.keyClick`.
- The smoke log scan fails on any `TypeError`, `ReferenceError`, `ERROR:` or
  `CHECK FAILED` (`tests/qml-smoke.py`, near the end).
- Keep `Commons.Color`: a bare `Color` breaks on Qt 6.12 (#20).
- Never stage, commit or push from the coder. The lead commits after each step.

## Steps

1. **`PipelinesModel.js`**: add `function zoomStep(percent, direction)` as
   above. In **`tests/model.cjs`**, for every integer 75..200 and both
   directions, assert:
   - the result is a multiple of 10 or exactly 75, lies in [75, 200], and
     moves strictly in the requested direction (unless already at the limit);
   - there is no allowed level between the input and the result;
   - `zoomStep(p, 0) === 100`;
   - the explicit sequence `100 → 90 → 80 → 75 → 75` going down and
     `75 → 80 → … → 200 → 200` going up.
   → verify by `node tests/model.cjs`
   Traps: none beyond ES5.

2. **`PipelinesPanel.qml`**:
   - add the root properties and functions from the decisions:
     `zoomPercent`, `zf`, `zs`, `zoomKey`, `onZoomPercentChanged`, and the
     test hooks;
   - wrap every `Style.font.*` pixel size in `root.zf(...)`;
   - wrap every `Style.space(n)` and `Style.spacing.md/sm/panelPadding` that
     sizes text, rows, indents or padding in `root.zs(...)`. These are at
     `:250-251` (inner term only), `:255`, `:288`, `:336` if it adds spacing,
     `:345`, `:350-352` and `:355`;
   - leave `:250-251` `Style.gapsOut`, `:253`, `:254` and `:332` untouched;
   - insert the `zoomKey` check at the top of both `Keys.onPressed` handlers
     (`:265` and `:306`), before their existing first line;
   - replace the footer `Text` (`:403-412`) with the footer `Item` described
     in the decisions.
   → verify by `python3 tests/qml-smoke.py`, which must still pass unchanged,
   then `nix flake check`.
   Traps:
   - put the zoom check before the existing `event.accepted = true` at the
     top of the list handler (`:266`), and keep that line for navigation;
   - the search placeholder `Text` (`:322-330`) inherits `searchField.font`,
     so it scales with no extra edit;
   - `rebuild()` uses `list.indexAt` geometry, so don't call it from the zoom
     handler.

3. **`tests/qml-smoke.py`**:
   - Add `import QtTest` and `TestCase { id: tc; when: false }` to the
     generated `shell.qml`.
   - Add a `binding loop` term to the log scan list (near the end of the file:
     `'ERROR:', 'ReferenceError','TypeError','CHECK FAILED'`), so a footer
     binding loop fails the run.
   - **Zoom fixture.** Add one new stage after the existing ones. It waits for
     `!panel.workerBusy && !panel.polling.flight`, then:
     - `panel.close()`;
     - `panel.polling = Polling.create()`;
     - `panel.polling.repos` set to 40 projects named `z/p00`..`z/p39`, each
       with `checked:"x"` and `runs:[]`;
     - `panel.polling.discover=false`, `catalogueComplete=true`,
       `catalogueAt=Date.now()`;
     - `panel.expanded = ({})` and `panel.filterText = ""`;
     - `panel.open("{}")`, then `panel.polling.cooldown = Date.now() + 3600000`
       so `Polling.next` returns `null` for the whole zoom phase;
     - `panel.adopt()`.

     Assert `panel.entries.length === 40`, and record `panel.polling.requests`.
     The last zoom stage asserts it is unchanged. The cooldown also makes
     `cooldownText` show, which the indicator check needs.
   - Each check below sets its own start: `Ctrl+0` first, then assert
     `zoomPercent === 100`. Focus goes to the list keys item unless the check
     says otherwise. After a zoom change, assert in the *next* 250 ms timer
     tick, so the `Qt.callLater` layout has run.
     - **Delivery:** `tc.keyClick(Qt.Key_J)` moves `panel.cursor` by exactly 1.
     - **List keys:** `keyClick(Qt.Key_Equal, Qt.ControlModifier)` → 110.
       `keyClick(Qt.Key_Equal, Qt.ControlModifier | Qt.ShiftModifier)` → 120.
       `keyClick(Qt.Key_Plus, Qt.ControlModifier | Qt.ShiftModifier)` → 130.
       `keyClick(Qt.Key_Minus, Qt.ControlModifier)` → 120. `Ctrl+0` → 100.
     - **Modifiers:** `Key_Equal` with Ctrl+Alt, then with Ctrl+Meta, leave
       the zoom at 100. Then a `j` still moves the cursor, which proves the
       keys were delivered.
     - **Search:** `panel.searchItem.forceActiveFocus()`, set `text = "ab"`,
       `selectAll()`, then `keyClick(Qt.Key_Minus, Qt.ControlModifier)` → 90.
       The text is still `ab`, `selectedText` is `ab`, and
       `searchItem.activeFocus` is still true. Then clear the text and return
       focus to the list.
     - **Scaling:** at 100, record six values:
       - `searchItem.font.pixelSize`;
       - the height of the first row delegate
         (`listItem.itemAtIndex(0).height`);
       - the card padding (`cardItem.padding`);
       - `cardItem.radius`;
       - the hairline (a `Rectangle` sibling; expose it as a hook
         `hairlineItem` in step 2 if it can't be reached);
       - the border width (from `cardItem.borderSpec`, or expose
         `borderWidth` as a hook).

       Press `Ctrl+=` five times → 150. The first three grow ×1.5, ±1 px. The
       last three are unchanged.
     - **Growth and cap:** at 100, assert `cardItem.width < window.width -
       2*Style.gapsOut` and the same for the height. If either is already
       capped on this screen, log `SKIP growth` and still run the cap check.
       Zoom to 120: both dimensions are larger than at 100. Zoom to 200: each
       equals `Math.min(Style.space(900)*2, window.width - 2*Style.gapsOut)`
       (and 680 for the height), ±1.
     - **Selection in view:** at 100, `panel.cursor = 39`, then
       `positionViewAtIndex(0, ListView.Beginning)` so that row is off-screen.
       Assert `listItem.contentHeight > listItem.height` (the list overflows)
       and that row 39 is outside the viewport. Zoom to 110 by key and wait a
       tick. `listItem.itemAtIndex(39)` is non-null, its `y` is at least
       `contentY - 1`, and its `y + height` is at most
       `contentY + listItem.height + 1`.
     - **Indicator:** at 120 (two `Ctrl+=`), with the cooldown from the
       fixture still active, narrow the card by setting `cardItem.width` to
       `Style.space(300)`, then wait a tick. Assert `hintItem.truncated` is
       true (elision really happens), `zoomItem.visible` is true and its text
       is `120%`, it lies inside the footer
       (`zoomItem.x + zoomItem.width <= footer width`), and
       `hintItem.x + hintItem.width <= zoomItem.x`. Then restore the card
       width binding by reassigning `Qt.binding(...)` with the decision
       formula, or close and reopen the panel.
     - **Survives close/open:** reach 130 by key, `close()`, `open()`: still
       130. Then `Ctrl+0`.
   → verify by `python3 tests/qml-smoke.py` three times in a row, all passing.
   Also check each zoom assertion fails on the step 1 commit (zoom code not
   yet present), for example by running against a `git stash`-free scratch

   Traps:
   - the zoom is per panel instance, and `fresh` and `managed` each start a

   - don't derive `hint` or `zoomLabel` sizes from `footer.height` or
